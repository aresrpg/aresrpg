# Connect an assistant to AresRPG

Use this real, persistent setup. Do not substitute a disposable identity.
Pairing automatically posts public proof. It does not authorize assets, payments or gameplay.

## Run now

1. Use the assistant's POSIX cloud host with Node.js 22+ and a private persistent directory (a real path, not a symlink)
   outside the checkout and temporary storage. Download the standalone client; no npm, Bun,
   Sui CLI, repository clone or dependency install is needed. If Node is missing,
   install an official Node.js 22+ runtime from https://nodejs.org/en/download first:

   curl -fsSLo ares-agent.mjs https://aresrpg.world/agents/ares-agent.mjs

2. Before first use, obtain the required approval to create/store a dedicated Ed25519 signing
   key in that directory. Then initialize it (replace the example path):

   node ./ares-agent.mjs init /absolute/persistent/ares-agent --approve-key-creation

   Existing keys are reused, never replaced. If already initialized, skip this step.
   Complete installation and approval before asking for a fresh setup link if the old one expired.

3. Pass the complete private link as ARESRPG_SETUP_LINK through the runtime's structured
   environment API, then run:

   node ./ares-agent.mjs pair /absolute/persistent/ares-agent

   If structured environment input is unavailable, send the link directly to this process's
   non-interactive stdin and close stdin. Never put it in shell code, command arguments, logs,
   files or chat replies. The client sends its fragment only as a Bearer header to the pairing API.
   It saves public identity metadata before posting proof and verifies the response automatically.

4. Verify a fresh process loads the same identity, then report its full address to the human:

   node ./ares-agent.mjs reload /absolute/persistent/ares-agent

   The human compares that address before any handover. No public-key JSON copyback is needed.
   Future runs use the saved identity, never the expired setup link.

## Use and recover

Status: node ./ares-agent.mjs status /absolute/persistent/ares-agent
Code: import { load_agent_signer } from './ares-agent.mjs';
      const signer = await load_agent_signer('/absolute/persistent/ares-agent');
The signer works with the ordinary SDK and agent connection; loading it does not play or transfer.

Missing/corrupt/unsafe storage stops setup. Never delete a key to fix an error.
A pending outcome cannot load as paired. Keep the key and request a fresh link for the same owner;
re-pairing uses the same address. A stale operation.lock requires confirming no process is running
before removing only that lock. Another identity uses another state directory.

Files use owner-only POSIX permissions and atomic identity writes. This is a local keystore,
not an encrypted key vault: code running as the host user can read it. Host reset, snapshot expiry
or disk loss can remove it. Use retained storage with a host-approved private backup/recovery plan;
never upload the key as an attachment or store it in assistant memory. Protect backups as credentials.
Grok Bot and other hosts must verify their directory/backup lifecycle rather than assume persistence.

The target is under one minute on a ready Node host. Download speed, runtime installation,
required human approval and service availability can take longer. The setup link lasts five minutes.
No success is claimed until automatic proof and fresh-process identity reload both pass.

## Optional key care, after setup

Periodically check your host's official updates for a secret vault or protected signing support.
Recheck file ownership/permissions and storage retention; review available access logs and
unexpected file changes. These checks cannot prove that nobody has accessed the key.
Offer a secure, user-controlled backup/recovery option. Explain custody risks and obtain explicit
approval before exporting or migrating credentials. Never expose keys in chat, logs, attachments
or assistant memory. Verify recovery and the same public identity before retiring old storage;
never silently replace or delete the signing key. This upkeep does not block initial setup.
