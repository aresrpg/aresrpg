# AresRPG active decisions

`ARCHITECTURE.md` owns the current system model. This file keeps active domain decisions whose motive
must remain durable. It contains neutral technical prose only: no transcripts, personal quotes,
personal attribution, or conversational incident history. Search the domain being changed; do not
treat the file as a second architecture. One line owns each decision. When a decision changes, amend or
delete its row; superseded decisions never remain.

- 2026-09-09 · ANIMATED LABEL BOUNDS SKIN ONLY GROUP HULLS: immutable GLTF geometry caches convex-hull boundary vertices per identical skin-index/weight group. Each group shares one affine skin transform, so its boundary preserves the exact animated bounds while avoiding a full mesh vertex sweep for every visible label. Position morph targets retain the full calculation because their hull can change.
- 2026-09-04 · RUNTIME TERRAIN MEMOS RETAIN LOCALITY, NOT TRAVEL HISTORY: every runtime mesh, planning, far-terrain, and main-thread compiler requests a 65,536-entry column FIFO—enough for the complete 56,644-column high-quality far grid—while offline generation may retain its broader working set. Structure candidates keep only 16,384 FIFO entries. Advancing evicts the oldest quarter in bounded batches; full-cache flushes, per-miss iterator churn, and duplicate caller-side column maps are forbidden. Offline generation and runtime use the same deterministic sampler, while cache policy changes neither terrain output nor authored content.
- 2026-09-04 · JOB LEVEL-UP IS A GLOBAL CYAN CEREMONY: every increase derived from an existing character's canonical job-XP level—whether folded immediately from crafting or arriving in the post-gather roster—queues one global profession card; initial login snapshots and non-increases stay silent. The card shows the complete crossed range, queues simultaneous gains, and uses a cyan/teal grid identity distinct from the fight card's ember/gold ceremony.

## Patterns — how to think here

- 2026-09-07 · KARES OUTLIVES GAME DEPLOYMENTS: monetary authority and counters survive game-authority rotation. Allocation remains 400,000 sale, 160,000 liquidity, 200,000 staking, 30,000 team, 110,000 community and 100,000 combat. Atomic setup prevents a separate freeze from stranding Genesis; participant-triggered settlement prevents treasury absence from blocking claims. Quiet combat days create no emission debt, and community vesting cannot depend on claim cadence. Metadata authority permits presentation changes without restoring mint authority. [Architecture](ARCHITECTURE.md#kares-and-the-offering) owns the monetary contracts; [offering operations](CONTENT_UPGRADES.md#kares-offering-operations) owns setup, funding and activation.
- 2026-09-09 · LEADERBOARDS KEEP ONLY CURRENT MONTHLY ACTIVITY: checkpoint timestamps assign UTC calendar months. Rollover deletes previous ranking tables; there is no historical query or season identity. The page shows ranks 1–100 even when empty and a day-based reset countdown. Character transfers never move earned combat or job XP. Mob kills and dungeon completions deduplicate participating characters by fight and address; delayed settlements cannot earn the same completion after reset. Marketplace volume uses positive public Kiosk purchase receipts, including nested calls; mandatory sale proofs bind the source kiosk and its immutable personal owner. Exclusive listings and private trades are excluded. Optional SuiNS names decorate rows without becoming identity or eligibility. The Monument podium keeps all three places visible in 2–1–3 order, including empty slots. Its surfaces and accents use the shared app tokens; the ranking table has three columns with the own-player marker beside the name. Names and badges share a short deadline so they cannot block score refreshes.

- 2026-09-06 · REWARD TIME MEANS ACTIVE STAKING TIME: a zero-principal pool pauses its clock instead of awarding an empty-period backlog to the next entrant. The initial stream and bounded supplementary daily buckets share that clock; cumulative per-asset indexes preserve earned rewards across principal changes and claims. Public top-ups use existing inventory, never new minting.
- 2026-09-06 · THE OFFERING HAS ITS OWN DEPLOYABLE: the public sale must boot independently of game startup. Neutral finance exports keep its SDK dependencies acyclic; staking and encyclopedia education stay in the app, with staking inside its persistent shell. - 2026-09-02 · JOB INGREDIENT LINKS FOLLOW THE NEXT PLAYER ACTION: clicking a raw, gathered, or dropped ingredient opens that item in the encyclopedia; clicking an intermediary resource selects its effective crafting profession and opens that recipe inside the Character Jobs detail, where the existing affordability, level, and transaction gates remain authoritative. The compiled catalog's resource kind and effective recipe job decide the destination; UI labels never infer it.
- 2026-09-01 · MASTERY IS ONE ADDRESS-WIDE EPOCH QUEST: a sender chooses any WorldContent that one free owned Character can enter; terminal Sui randomness assigns one unique city dungeon from that world, and the world's entry level snapshots a 1/2/3/4/5-point reward at levels 1/51/101/151/200. Once assigned, the quest card retains that world's landscape and explicitly names the dungeon to find and complete for the points. Any owned winner may validate it only through a final-room Fight created in the assigned world strictly after the quest, so a parked victory cannot be claimed retroactively. Assignments expire at epoch rollover, but skipped epochs carry no penalty: Mastery points are one durable cumulative balance and every eligible completion adds its reward. Derived MasteryOffer objects reference statless item templates and retain an immutable authored cost. Either earned points or the same number of whole KARES buys the same item into the personal kiosk; KARES is burned and never changes earned points. Availability remains mutable, and retirement cannot rewrite the price. Their presentation is an equal-height responsive shop grid with item, price, affordability, and one purchase action; no spine or alternating timeline implies a false unlock order. The item face opens its canonical encyclopedia detail, while the separate Buy button spends the explicitly selected currency. Incoming snapshots cannot reopen an in-flight redemption. Loot boxes retain their separate open/claim randomness; an empty loot-box table fails publication validation until its rewards are authored. Owner receipts reconcile live writes; the indexer/server provide only the reconnect snapshot and current indexed epoch.

It also pins the Sui CLI release and Linux archive checksum; local artifact compilation checks that release before building. Math owns pure values; control owns administrative authority; combat owns only deterministic authority-free fight state; seed owns living content objects; core owns UID, key, custody, transfer, event, clock, entropy-source, and transaction-context authority. CI, SDK publication, pins and coverage cover all six slots. Game republishing cycles only math, control, combat, seed and core; it retains the independent KARES lineage. Every package has the same 96,000-byte raw-bytecode ceiling, preserving metadata headroom below Sui's 102,400-byte object limit; package-specific budgets and compressed atom names are forbidden.
- 2026-08-31 · FIRST-OPEN GUIDANCE IS ONE DEVICE-LOCAL COACH-MARK SYSTEM: the creation welcome remains the empty-roster entry, while one global host derives the next unseen tutorial from loaded page and fight truth, highlights stable semantic DOM anchors or the engine-projected active character, and blocks underlying input until that sequence is finished or skipped. - 2026-08-16 · FIGHT PRESENTATION IS ONE ORDERED CUE EDGE: canonical local, streamed, and reconciled fight events project once into immutable cues; the game owns their serial queue, the engine owns model beats and one bounded typed VFX primitive, and the frontend owns audio. Persistent effects derive from the checkpoint, never presentation state, and local mode changes only the fight input source.
- 2026-08-15 · ENTITIES HAVE ONE ENGINE DOOR: terrain and fight boards submit the same plain entity spec with a world or fight-cell anchor; the engine alone loads and animates mob or character models, and a character appearance owns its body, optional Head-bone hair, three colors, and Head/cape worn cosmetics
- 2026-08-16 · FIGHTERS FACE THE OPPOSING BAND (legacy parity): placement orientation is layout-independent — every fighter declares its side through the shared entity door, and the engine faces it toward the opposing starting band centroid with `atan2(Δx, Δy)`; simulator-specific yaw constants are forbidden
- 2026-08-15 · FIGHT-BOARD BLOBS HAVE ONE ENGINE DOOR: placement cells, ranges, spell AoE hovers, glyphs, simulator probes, duels, and Kolizeum all create colored `single` or inset `per_cell` areas through the shared fight-board API; spell AoE hovers are always one red `single` shape, per-cell reveals travel outward from an origin and reconcile updates by cell identity, and any single area grows as one cartoon shape; overlapping meanings use explicit blob priority and remove covered cells from lower translucent layers; the engine batches each per-cell area into one instanced draw while retaining per-cell reveal identity — callers supply cells and meaning, never another renderer; fight code owns cell semantics, while the engine owns geometry, reveal, replacement and removal. HUD- or mode-specific overlay renderers are forbidden.
- 2026-08-17 · FIGHT STATUS VISUALS CROSS ONE PLAIN-DATA DOOR: fight state decides which entity carries a status visual, while the engine owns its pixels; allied invisibility supplies `{ kind: 'invisibility' }` and reuses the retained skinned heat-haze treatment without remounting the model. Enemy and spectator projections omit the entity as casual tactical presentation; chain state remains public.
- 2026-08-17 · INVISIBILITY BREAKS ON IMMEDIATE DAMAGE: only a cast that resolves direct damage consumes the caster's invisibility; placing a trap or glyph stores its damage for a later zone resolution and never reveals the caster at placement time. Move and the local fight twin share this predicate.
- 2026-08-16 · FIGHT PREVIEWS COME FROM FIGHT TRUTH: the fight package derives steered movement paths and exact spell targetability from the same rules the command resolver executes; the game submits that path unchanged and maps projections to the shared blob API, while the engine animates accepted `fighter_moved` events through the one entity door. A hovered fighter temporarily owns the displayed MP range; the active fighter path appears only when no fighter hover overrides that range.
- 2026-08-16 · CRITICAL DRAWS ARE PER TURN AND SPELL: Move and the fight mirror derive one stable critical roll from the public turn seed plus canonical spell name; target and cast slot never enter that key, so aiming or repeating a spell cannot reroll it, while different spells can differ during the same turn
- 2026-08-16 · SPELLS MAY TARGET EMPTY CELLS: range, launch-line, line-of-sight, AP, cooldown, and cast caps decide whether an anchor is castable; a living occupant is never required. Empty-or-occupied REQUIREMENTS live on the effect kinds that own them, never on a spell flag: a trap anchor aborts on a living occupant, teleport no-ops onto a body, swap needs one — so the authored `free_cell` field is retained wire data with no rule behind it. AoE previews run the real fight resolver on a disposable checkpoint, so affected-fighter nametags never duplicate shape, target-filter, roll, or damage rules in the UI.
- 2026-08-16 · FIGHT GAIT USES THE WHOLE ACCEPTED PATH (legacy parity): one or two cells use the WALK clip at 480 ms per cell; three or more use RUN at 170 ms per cell — derive gait once before playback so segmentation never reclassifies a run
- 2026-08-16 · SIMULATOR TURN RESET IS A LOCAL CHECKPOINT: reset restores the exact checkpoint, render identities, and deterministic seed cursor captured at the current player-turn boundary inside `@aresrpg/fight`; it is unavailable in remote mode and never enters the wire
- 2026-08-15 · SIMULATOR ROSTERS SURVIVE RELOADS: locally authored simulator characters live in the existing `aresrpg_simulator` IndexedDB roster store and hydrate through the simulator reducer; board placement and fight state remain ephemeral

- 2026-08-14 · SEED PHYSICAL LAYOUT: `seed/` has exactly four authored homes: `content/` for domain JSON, `icons/` for images, `models/` for geometry, and `sounds/` for audio. There is no `assets/` wrapper and no `sprites/` folder; semantic subdirectories exist only to prevent collisions or group real model families.
- 2026-08-14 · MOB ICON IDENTITY: `seed/icons/mobs/` contains the canonical mob icons only. Model-source `hy_*` renders are duplicate previews, not another asset family, and do not belong in the repository.
- 2026-08-14 · MODEL ASSET HOME: every authored 3D model lives under `seed/models/`. - 2026-08-18 · FOOTSTEPS FOLLOW MATERIAL PRESETS: world roaming accumulates grounded horizontal distance and renders a subtly varied footstep from the sampled terrain, structure, or liquid `MaterialPreset`; the preset list is the coverage contract. One speed-driven heel/toe-plus-friction exciter feeds the material response: modal resonances for solids, stochastic particles only for aggregates, and descending bubbles for liquid. When synthesis lacks ecological validity, a small proven or CC0 recorded impact set may replace that preset's exciter from the flat `seed/sounds/` corpus, decoded once and provenance-recorded; cadence and material selection remain shared. Footsteps add no parallel block-name taxonomy, timer cadence, fight-board duplication, or per-frame audio graph.
- Take facts from the context, never as parameters: the sender lives in `ctx` — a parameter that repeats what the context knows is a redundancy that can lie
- Flatten until forced: no wrapper struct for three colours, no subfolder for one package, no explicit dependency the toolchain injects itself — hierarchy must earn its existence

- Latest of everything, no duplicates: lean on toolchain defaults over manual pins; a pin is a scar, not a habit
- The pattern library is the aresrpg-legacy repository (the original testnet game — lean, proven; the frozen move-old/rpc-old trees live in git history) · before designing any mechanism, check how legacy solved it and carry the pattern, not the code

The general orchestration boundary is recorded under PTB-SAFE ORCHESTRATION BELONGS IN THE SDK.

## Decisions

- 2026-08-23 · LIVING CONTENT STAYS OUT OF LOGIC: cap-gated object mutation permits rebalancing without replacing package logic. Core consumes accessors; copying mob kits at engage, boards at fight creation and unique rolls at mint protects historical outcomes. Stackable live behavior is recorded under STACKABLE BEHAVIOR IS LIVE, UNIQUE VALUE IS SNAPSHOTTED. [Package ownership](ARCHITECTURE.md#package-ownership) owns the graph; [immutable identities](CONTENT_UPGRADES.md#immutable-identities) owns retirement constraints.
- 2026-08-23 · FREEZE_FOREVER IS THE ENDGAME SEAL: ONE irreversible cold-key-only door sets `frozen` on the seed registry root; every content door asserts it through `registry::bump`/`uid_mut`, and the supply doors will assert the same flag through the registry's cap-gated claim/bump seam. No unsetter exists; a daily temp cap can never pull it. The mechanism ships and is tested from v1.
- 2026-08-23 · CAST IS THE SANCTIONED LIVE-READ: player casts read `&SpellTemplate` live — a full spellbook is too big to snapshot into the Fighter and the layout change would drag the indexer. A mid-fight spell rebalance lands on the next cast, abort-clean, twin-visible via the registry revision; the rebalance composer refuses spell/mob writes while wagered kolizeum lobbies are open (money guard — Move-side is impossible, seed cannot see core's lobbies).
- 2026-08-23 · FIGHT BOARDS ARE AUTHORED CONTENT: `seed/content/fight_boards.json` is the ONE authoring home — the validator proves full connectivity offline, `combat_grid::grid_spec` holds the cheap on-chain sanity floor, the catalog stores one dynamic field per board (dense indexes by construction, add/replace, never remove), every creation door picks `boards[seed % len]` and COPIES into the Fight, and the simulator reads the same JSON. On-chain generation is dead (test-only fixture machinery now) — it was 70–89% of fight-creation gas with a seed-dependent 16× cost tail.
- 2026-08-23 · THE FIGHT GAS BASIS IS 0.02 SUI: the reference 12-turn/3-mob PvM fight must net under 0.02 SUI; real fights keep unlimited turns and up to 6 mobs, and no lever may cap either for gas. Ephemeral movement searches retain BFS layers as two-word bitsets, with the same distances and lowest-cell route ties; they add no stored Fight fields. Individual stat reads adjust only that stat and applicable power, and each adjustment folds effects once. Gas regressions preserve captured input and expected output bytes and run under an enforced budget; comparisons use trace gas deltas because CLI test statistics mix units. Runtime spell targeting is FIGHTER-FIRST: each effect checks at most the twelve fighters once through one constant-time zone rank, preserving historical target order; board-cell enumeration is test/presentation machinery and never a resolver input. Constructors cap an effect branch at eight rows, area size at ten, AP cost above zero, and a conservative base-AP mob estimate of ten row-casts. Runtime mob work uses the Move-owned row ceiling and the existing per-actor cast ledger; each cast reserves the kit's largest normal-or-critical branch, with a minimum of one row. This preserves ordinary validated AP-scaled kits while AP refunds cannot prolong a turn without bound. Runtime-shaped White Ant and general-wave gas tests ratchet these bounds. The last mile is the close door's storage rebate (participant-only — an open door lets bots farm player-funded deposits) and the bounded mob AI; the irreducible floor is Sui's ~0.0016 SUI per transaction × one transaction per player turn.
- 2026-08-22 · THE CHALLENGE IS THE INVITATION: `challenge_duel` names the target and reserves side B for that character (`ACCESS_INVITED`), so the Fight object carries the invitation and the challenged client reads it from the streamed fight row. Sword discovery remains public. During placement the modal shows both teams and lets chain access enable each join control; after start it offers spectate. A challenge costs gas before consent, and a refused duel leaves the challenger on their visible board to leave.

- 2026-08-22 · THE GATE IS DRESSING, THE CHAIN IS THE BOUNCER: every world's portal renders unconditionally at client 0;0 as engine dressing (one TSL disc, sunk into the terrain, exits with the flatten's water phase) — no per-world config exists to drift; the approach prompt is PROXIMITY-gated, never cursor-hover. The travel surface is a small grid of real landscape cards whose generated art is presentation-only; authored worlds still own identity, biomes and entry level, and the chain reasserts every lock. Arrival folds only from `WorldJoined`, and the refreshed roster anchor remounts the destination surroundings.
- 2026-08-21 · ONE RESOLVER SIMULATION, ONE FIXED GAS BUDGET, GAS COINS ARE THE RESOLVER'S: the official Core resolver selects gas and simulates the unsigned transaction once before the wallet opens; the SDK must not simulate those resolved bytes a second time. A successful resolution signs once and submits once. `GAS_BUDGET_MIST` is pinned at 0.2 SUI, so no estimation simulation is needed. The SDK NEVER names the gas coin: which coin — or whether a coin exists at all, since an address may hold its SUI as an address balance instead of `Coin` objects — is the Sui resolver's answer, and pinning one receipt-fresh ref with no fallback is what told a wallet holding 1000 SUI it was out of gas. SUI spending splits `tx.gas` after native gas consolidation; KARES spending uses the official `coinWithBalance` intent to combine Coin objects and address balances before payment. Neither path adds a separate wallet-wide consolidation transaction or pins a single funding coin. A resolver simulation refused for gas is OUR budget, not the player's wallet: it raises its own toast and must never read like an empty balance.
- 2026-08-21 · ADMIN OVERVIEW READS ARE WALLET-FREE, THE TREASURY IS A NAME: every chain-readable fact on the admin page (treasury balance, policy royalty balances) loads immediately through the SDK's read-only client—the one sanctioned direct Sui GraphQL path for this surface—and a browser wallet connection exists only to claim royalties. The treasury address is never hardcoded off-chain: it resolves from SuiNS (`treasury@aresrpg`) lazily when the admin page loads. Off-chain metrics wait for their server route, never a chain workaround.
- 2026-08-26 · SOCKET QUARANTINE ADMITS ONLY THE PROOF: WebSocket `OPEN` is transport state, not authentication. Until `packet/connection_accepted` arrives, the public link door returns false for every application packet; only the internal response to that socket's signature challenge may send. Navigation, market observation, chat, presence, or any other UI state change during verification therefore cannot become `INVALID_PACKET` and falsely clear a valid wallet as `could not verify`. Transport open never resets reconnect backoff; only authenticated acceptance does, so repeated local proof interruption reaches the 30-second cap instead of hammering one-second sockets.
- 2026-08-20 · ONE SEAT PER ACCOUNT, THE EVICTED WINDOW STAYS DOWN: the server keeps one socket per address (same-pod `REPLACED`, cross-pod `ALREADY_CONNECTED`); the kicked client parks the link in a terminal red state with a `connected from another place` modal and NEVER auto-reconnects — a retry would only steal the seat back and ping-pong both windows. Reconnecting is an explicit human action.
- 2026-08-20 · THE SDK IS WRITE-FIRST, THE WIRE IS SNAPSHOT-THEN-DELTA: the SDK reads chain state only for transaction-building facts (object refs/versions, balances) and two explicit one-shot presentation exceptions: Party run-to snapshots one external character checkpoint in parallel, while a linked chat Item tooltip reads that exact original-package object plus its rolled-stat field through a 20-entry authenticated-session success/in-flight LRU. The independent wallet-finance surface additionally reads its pinned Currency, offering, staking pool, owned positions, balances and clock through the SDK before game publication; that exception never becomes a gameplay read fallback. Everything else a player sees comes from indexing through server packets; the inventory loads ONCE at boot and then moves only by per-item add/update packets (packet/item_updated, the bounded packet/items_request for receipt-named ids) — never a bulk re-push. Pending claims settle SILENTLY (modules/claims.ts) with zero claim UI; an empty gas tank raises the one blocking top-up modal.
- 2026-08-20 · CONTENT EDITION LIVES ON /DEMO; RELEASE WRITES HAVE NO BROWSER PATH: the local composition lab covers every seed field, including dungeons and biomes, through development file doors and renders the edited recipe. Production admin retains analytics, sales history and royalty-wallet actions only. Keeping publication, reconciliation, pause/resume and permanent freeze in private release tooling prevents the authoring surface from acquiring chain authority. See [content](ARCHITECTURE.md#content) and [the release checklist](CONTENT_UPGRADES.md#upgrade-checklist).
- 2026-08-20 · THE SEED EDITOR AUTOSAVES; GIT IS THE UNDO: no save/reset/duplicate/delete/raw-JSON ceremony — every edit lands on disk after a short settle (the validator still refuses saves that introduce new reds; a refused value retries only once it changes), and a seed save never reloads the editing client: the dev server suppresses the JSON-module reload and emits an event, the /demo lab defers its reload to the next tab switch so the labs pick up the rebuilt seed exactly when they need it.
- 2026-08-20 · A FULLY FED PET GIVES STATS: every pet item authors a stats block — seed validation reds a pet without one; the editor offers the full stat sheet on any stat-eligible item and authors the total zeroed block on first touch (a first stat starts fixed, min = max, so no transient ever violates the range law).
- 2026-08-20 · ONE FIGHT SYSTEM, THE ONLY SPLIT IS LOCAL VS REMOTE: duels, PvM, dungeons and kolizeum all flow through the same client fight core; a remote fight hydrates from the indexer's projected machine document (contract off the wire + player sources from Character nodes' CHAIN-OWN folded stats + spells from the local seed catalog) and every local input becomes one chain transaction while the mesh relay only smooths the other screens. The runtime is the packet's single numeric normalization door: every presentation and result consumer reads its bigint-native checkpoint, never the raw JSON object handed into it. Never a per-mode fight path.
- 2026-08-19 · TRAPS FIRE ON ENTRY ALONE: a trap triggers only when a fighter ENTERS one of its zone cells; since every mover resolves per step, crossing the zone always touches it, and stepping off the edge touches nothing and stays silent. The departure cell never arms a trap — in Move and the local twin alike.
- 2026-08-19 · CHATIMENT USES THE RETRO DAMAGE CAP WITHOUT EROSION: kind 7 is CHATIMENT; actual nonlethal HP lost becomes the authored characteristic up to the summed same-stat stance cap once per active fighter turn, never once per hit or once per stance. Player-sourced damage feeds half its landed value under half the cap; mob-sourced damage feeds in full. Each turn folds into one five-turn gain row, so later turns stack with independent expiry; the normal rank caps are 60/80/100/120/140/200 and critical caps 70/90/110/130/150/220. Ares deliberately omits Retro's erosion rider.
- 2026-08-19 · LIFE STEAL DRINKS HALF: an instant hp steal heals its caster exactly half of the damage that actually landed, floored — never the full hit, never overkill.
- 2026-08-19 · ONE OWNER PER TRANSFORM (engine): an entity's root POSITION belongs solely to placement (place/snap/motion); presentation beats animate only the inner wobble node around identity and capture no rest state. Facing (yaw) is deliberately retained placement state, not a beat capture.
- 2026-08-19 · POOL DELTAS FLOAT FROM EVENTS, ONCE (frontend): floating AP/MP numbers project from `ap_mp_change` (effect reasons only) plus the lasting-row event when no live pool moved — one signed float per fighter per resolution segment; costs, refills, and tackle keep their own presentation.
- 2026-08-19 · THE TRAP ZONE IS THE PAYLOAD'S AREA: one authored fact (the trap's shape/size) decides trigger, display, and effect area — the resolver rewrites payload rows to the zone's geometry and never trusts a second authored area copy; glyphs stay per-occupant. Both twins.
- 2026-08-19 · THE LOG SPEAKS EFFECTS, NOT CONSUMPTION: the combat log shows only what fighters do to each other — contested AP/MP removals speak through `points_contested` (loss, partial dodge, full dodge, steal all visible; a full dodge is emitted truth, never silence); a hit line merges its shield reduction (for example, `lost 45 HP (reduced 5)`), returned spells and lasting stat changes get their own lines; casting/walking costs, refills, and turn switches stay silent.
- 2026-08-19 · ONE CHAT FOR THE WHOLE GAME: a single chat module is the only message history; every stream that speaks to the player (combat log today, world chat later) feeds it as SEMANTIC lines (template key + tokenized values) so the renderer localizes live and paints tokens from one palette; a line is corrected only through the explicit `replaces` door, never by inference. Mounted in the fight HUD until a world HUD exists.
- 2026-08-23 · TEAM RINGS FOLLOW THE PLAYED TURN: every living fighter carries a subtle border-only ring in its team color under its cell; the stronger pulse follows whichever fighter's turn cue is currently being played, including mobs and opponents. Canonical future state never moves or removes a ring before its matching movement or death cue completes; that death then removes the fighter from model sources, so refresh, HMR, and later cue updates cannot resurrect it.
- 2026-08-19 · THE MOB TURN FLOOR IS ONE CONSTANT: the chain already prices every mob turn at TURN_MIN_MS into `turn_started_ms` (and the twin mirrors it); presentation holds the turn card to the same projected `min_ms` on the turn cue — no second clock, no client-side invention.
- 2026-08-19 · COOLDOWN IS LOUD: a spell on cooldown shows its remaining turns as a big centered red number over the card.
- 2026-08-19 · DISPLACEMENT SLIDES: push/pull presentation is a fast slide—no locomotion clip, no reorientation; being shoved is not walking. Teleport/swap stay snaps. A blocked push deals exact Retro 1.27/1.29 collision damage `floor((8 + R·pusher_level/50) × untravelled_cells)`, with `R∈1..8` drawn from the effect's existing deterministic turn-seed stream; Ares has no dedicated push-damage/resistance stats, so those two terms remain zero.
- 2026-08-19 · INDEXING SETS + THE MESH SPLIT (amended 2026-09-04): the read layer is N identical self-contained indexing sets (one FalkorDB + its one indexer per pod, per-pod volume). Reader processes boot without waiting for the projection to reach the live edge; their server exposes cached checkpoint lag, while the client owns the explicit unknown-or-over-300 interaction barrier and catch-up presentation. A connection stays bound to one set for life, and a server whose set dies kills itself so orchestration can replace it. Event publishing is split by publisher: chain evt:* rides each set's OWN redis (never a shared bus — N sets would duplicate every event ×N, and cross-set delivery would outrun the reader's own graph), while player ephemera + heartbeats ride the ONE cluster mesh redis. A heartbeat stores one short-lived authenticated-address snapshot per pod and online count is their identity union, so rolling replicas cannot multiply a player; mixed legacy numeric heartbeats contribute only a maximum floor during the first rollout. Player events still have one owning publisher and need no generic dedup, blue/green, or leader election.
- 2026-08-20 · WORK CONVERGES ON ONE EDGE: `edge` is the repository default and only persistent branch; contributors submit PRs to it, while the owner is the sole human ruleset bypass and may push signed commits directly. Contributor PRs require the owner's CODEOWNER approval after the latest push, resolved conversations, and every gate check; feature refs never deploy. Production authority belongs to owner-created semver tags, not another branch.
- 2026-08-19 · SPEED IS PRICED FROM AN ANCHOR, NEVER PER SAMPLE: the stream speed law mirrors the chain's travel_ok — distance from the last PROVEN position over elapsed since it (anchor seeded by the checkpoint's OWN timestamp, re-anchored at most once per second, small named transient slack). An unchanged chain checkpoint preserves the connection's validated walking position and movement allowance across roster rereads. A new checkpoint synchronously replaces both before the roster reaches the client. Movement packets name their character and exact world/checkpoint identity; stale packets are ignored before speed validation, so recall cannot turn in-flight walking into a speed violation. Instantaneous per-sample speed checks are banned: physics transients legally exceed the budget for one frame. Violation drops use the one protocol-declared reason set and paint the connection card red.
- 2026-08-22 · EVERY POSITION FACT NAMES ITS CHARACTER: `packet/position` carries `character_id`; coordinates never inherit identity from ambient connection state. The server routes it only through that tracked character's proven ownership and checkpoint anchor, so simultaneous characters cannot price coordinates against one another. Client throttling is keyed per character for the same reason.
- 2026-08-19 · ZONE POPULATION IS SERVER-DERIVED, SERVER-SENT: the seed→spawn derivation (zone_math.move) has ONE TypeScript twin, in the server (`zone_spawns.ts` — same prng, same draw order, same ramps; a zone_math.move change lands there the same commit). The client never derives: it receives `packet/zone_spawns` when a discovered zone enters its tracked spiral and again the instant a tracked zone is searched (fresh seed = fresh, unconsumed spawns). Presence and spawn payloads ride the zone-keyed channels — the legacy chunk-tracking pattern, on zones.
- 2026-08-19 · POSITION RESUMES LOCALLY UNDER THE CHAIN'S ANCHOR: the chain checkpoint is the only authoritative resume point; an IndexedDB row keeps the precise local pose, honored ONLY while it explains itself — same character/world, captured under the exact current chain anchor, under 30 minutes old. A character retains one checkpoint DF per visited world, but the graph promotes only the checkpoint matching `CurrentWorldKey` into the active `checkpoint_world/x/z` fields: a same-transaction world sibling makes travel order-free, while a lone checkpoint update is graph-guarded by the current world. A stale remembered world can never force refresh into spectator mode. Live and follower poses carry the same checkpoint identity as movement packets; a pose from another checkpoint cannot be displayed or saved under the current one. Chain truth moved = the cache is stale, checkpoint wins. Unversioned resume rows are ignored because their old writer could stamp pre-recall coordinates with the new anchor. Never localStorage: positions are data, preferences are localStorage.
- 2026-08-19 · THE WORLD HUD READS TWO LANES: per-frame presentation (pose, heading, fps, time-of-day) rides a throttled external feed outside the app reducer; server facts fold through the one world reducer. The north-up minimap owns coordinates, searched-zone veil, delimitation, mob/resource markers and live players; every marker projection takes the selected world explicitly, so retained discoveries from another character/world cannot bleed through. Public/party engage preference lives beside quality/flat controls, never inside a mob nametag.
- 2026-08-19 · CHARACTER SELECTION IS APP-WIDE CHROME TABS (amended 2026-09-04): one tab strip at the top of the page area — one tab per owned character, a plus tab that opens character creation — is the ONLY selection door, shown on the character-scoped pages (world, characters, kolizeum). Opening creation atomically returns navigation to its World host, so the plus tab has identical behavior from every surface where it appears. Every character remains server-tracked; selection is a local projection that re-points rendering, camera, gear, stats, spells and jobs through one `character/select` reducer input. No second selector and no selection packet exist. The characters page contains only selected-character details, never another roster list.
- 2026-08-19 · RESIST IS PERCENT AND SAYS SO: resistance rows are percentage points cutting final damage; every displayed resist number carries the % unit, derived in one helper — authored copy never hand-writes the unit.
- 2026-08-19 · ROUNDED BLOCK EDGES ARE A NORMAL TRICK, NEVER GEOMETRY: block corners read rounded via the legacy engine's fragment-normal bevel — the mesher flags each greedy quad's convex edges (word B bits 28-31; an edge is convex only when every cell along it borders empty space in the face's plane), and the terrain shader bends the normal within a 0.3-block margin of flagged edges, written as branchless arithmetic (the WebGPU normalNode select-chain trap). Voxel positions, collision, and shadows never change.
- 2026-08-19 · GROUND CLUTTER DERIVES, NEVER AUTHORS: terrain decoration (grasses, ferns, sedges, bushes, flowers, mushrooms, twigs, pebbles, ice spikes) is a pure function of what the column already is — the visible top material's preset picks the kind, its authored colors (hue-shifted, scaled) paint it, and the shader applies the same climate-tint field as the ground. No sprite palettes, no per-biome decoration config, no textures; a new biome gets fitting clutter for free from its materials. Amendment: the sprites are PIXEL ART, because this is a voxel game — plants are crossed pixel-planes (cell-drawn silhouettes, stepped edges, three quantized color bands), minerals are stacked axis-aligned boxes; each sprite is one file under `packages/engine/src/nature/` (shared machinery in `sprite_kit.ts`), and a kind's variant pool mixes several sprite species so neighbours never twin. Density rides a two-octave sharpened field (broad meadow waves + fine patches, true bare gaps — never a linear fade), and dense patches also grow taller.
