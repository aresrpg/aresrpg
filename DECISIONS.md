# DECISIONS — the owner's mental model

This file makes any agent think like the owner. Patterns first — they decide the calls he is
not in the room for. Rulings second — settled choices, never re-derived, never undone silently.
One line each. A new entry lands the moment a choice carries a motive worth reusing.

## Patterns — how to think here

- Derive, don't register: identity comes from deterministic derivation over natural keys (a character's address = owner + name under the gate) — findable without an indexer, unique by construction; a registry table is a smell
- Public data files are pure data: a served JSON carries only fields a consumer reads — no prose, no ruling dates, no authorship trails, no internal references; provenance lives in git history, which already does that job
- One content home, HARD LAW (owner 2026-08-12): `seed/` holds the game's content truth — one file per domain, no version-stamped twins, no pointer files, no frontend-side JSON copies; the frontend consumes seed/ through the build (a generated artifact is derivation, a committed copy is a violation)
- 2026-08-14 · SEED PHYSICAL LAYOUT (owner): `seed/` has exactly four authored homes: `content/` for domain JSON, `icons/` for images, `models/` for geometry, and `sounds/` for audio. There is no `assets/` wrapper and no `sprites/` folder; semantic subdirectories exist only to prevent collisions or group real model families.
- 2026-08-14 · MOB ICON IDENTITY (owner): `seed/icons/mobs/` contains the canonical mob icons only. Model-source `hy_*` renders are duplicate previews, not another asset family, and do not belong in the repository.
- 2026-08-14 · MODEL ASSET HOME (owner): every authored 3D model lives under `seed/models/`. Model families use semantic subdirectories (`mobs/`, `characters/`, `cosmetics/`, `pets/`), standalone props live at the models root, and `cosmetics/` carries the complete canonical worn-model corpus rather than a frontend copy.
- 2026-08-14 · SOUND-EFFECT ASSET HOME (owner): sound files use the unabbreviated, flat `seed/sounds/` directory. There is no `sfx/` alias and no redundant `fight/` subdirectory; runtime fallback URLs may keep their public `/sound_effect/` contract as a build derivation.
- Take facts from the context, never as parameters: the sender lives in `ctx` — a parameter that repeats what the context knows is a redundancy that can lie
- Flatten until forced: no wrapper struct for three colours, no subfolder for one package, no explicit dependency the toolchain injects itself — hierarchy must earn its existence
- Denormalize for the reader, with exactly ONE writer: `level` sits on the character so wallets can read it; only the progression door writes it, in the same transaction as the xp it derives from
- The module boundary is the security boundary: data modules own shape and invariants behind public(package) doors; gate modules own policy (names, prices, whitelists); consumers compose doors
- Gas outranks storage purity: players pay computation forever, while storage deposits refund on deletion — snapshot sealed data into short-lived objects freely, never recompute per action what a stored copy answers; derivation is for LIVE state that can drift
- Latest of everything, no duplicates: lean on toolchain defaults over manual pins; a pin is a scar, not a habit
- The pattern library is the aresrpg-legacy repository (the original testnet game — lean, proven; the frozen move-old/rpc-old trees live in git history) · before designing any mechanism, check how legacy solved it and carry the pattern, not the code
- PTB-safe stays OUT of the modules: anything a frontend PTB can do safely never pollutes Move — a Move signature must ask only for what it genuinely needs. Personal-kiosk custody is a publish-time transfer-policy rule (`personal_kiosk_rule` + `kiosk_lock_rule`), which natively forbids an item leaving for a non-personal kiosk; therefore doors take a bare `&KioskOwnerCap` (provably a personal kiosk's soulbound cap) and `PersonalKioskCap`/`personal_kiosk::borrow` live only in PTBs — threading the wrapper through Move buys zero extra safety

## Rulings

- 2026-08-14 · ENGINE DISPLAY BOUNDARY + VOXEL STREAMING (owner): game core owns world focus, 3D chunk identity, desired near/mid/far residency, and bounded scheduling; `@aresrpg/engine` owns meshing workers, GPU resources, visibility, atmosphere, and every displayed effect behind one plain-data API — no Three.js type crosses upward. Resident chunks use a keyed bounded map and dense binary voxel words; surface LOD uses camera-centred rings, while octrees/BVHs are optional measured query indexes, never the foundational store. WebGPU is the sole real renderer; unavailable/failed WebGPU displays only the tiny flat retrowave-grid presentation, never a second terrain implementation. Every quality tier is sub-native and one capability plan selects its render scale, residency, shadows, effects, and accelerated implementation; switching tiers retains the renderer and overlapping chunks.
- 2026-08-13 · SDK DOMAIN BUILDERS (owner "let's make a builder"): each stateful chain domain gets a builder — `trade_actions(sdk, {row, address, kiosk_cap, execute})`, `character_actions(…)` — whose methods compose the PTB, execute through the app's one signer door, and return `{digest, row}`: the next rendered row derived from the action's OWN inputs. Rebuild the builder from the fresh row after each action (an accept pins exactly the version it rendered). No parameter trains, no per-door free functions in the app
- 2026-08-13 · RECEIPTS TELL, NEVER GUESS (owner): a client folds from a receipt exactly what the receipt CONTAINS — event fields, plus its own input deltas applied to rows it already holds — and NEVER invents chain-initialized state (a created character's starting row is Move's business, not a client mirror). The server never re-sends what a receipt told the client, and streams everything a receipt could not carry: other players, external state, and the projected row of a freshly created object (CharacterCreated routes to the owner's social channel for exactly this)
- 2026-08-13 · POINTS ARE STORED AVAILABLE, NEVER SPENT (owner "move should only use available_spell_points, this was my rule"): Move stores the AVAILABLE balance for both stat and spell points as Character fields — granted on level-up, decremented on raise, refilled on reset; a lifetime-spent counter with a derived pool is the drift this ruling killed
- 2026-08-13 · THE SDK OWNS ALL SUI PLUMBING (owner): the app NEVER touches a @mysten library, never builds a chain client, never composes a PTB, and never reads a receipt — the SDK exposes simple functions with elegant object returns (composed tx in, projected rows/deltas out); receipt decoding and projection are SDK API, not app code. zkLogin arrives as a STANDARD wallet (Enoki registers it into wallet-standard) — no special-cased zkLogin path in the app
- 2026-08-12 · THE TRADE ESCROW (owner — kills transferred PurchaseCaps: "if you get ghosted, the item is locked forever"): p2p exchange = ONE shared Trade pinned to two addresses. Each side parks 0-price caps (items stay exclusively listed in their OWN kiosk — withdrawable any time pre-lock, so ghosting locks nothing) + optional SUI. EVERY mutation bumps `version` and voids both accepts; `accept(seen_version)` aborts stale — nobody locks on a state they did not read. Both accepts at one version LOCK the trade TERMINALLY: only counterparty claims remain (never expire — asymmetric execution cannot rug), then either party sweeps the drained husk. Claims chain the 0-price purchase + royalty floor + relock in one PTB. The 0-price purchases are market-invisible by the existing plumbing gate; CAN_BUY, ExclusiveOfferCreated, and the cap-deletion sale forensics are DELETED flows
- 2026-08-12 · CHARACTERS CHANGE OWNERS NAKED (owner): worn gear never rides a sale or trade — enforced as a CHARACTER-POLICY RULE (naked_rule: buyer borrows the just-locked character and proves it bare at transfer resolution, covering market AND trades), PLUS a fail-fast twin at the trade deposit door (an equipped character parked in a trade would pass the lock then abort every claim — locked forever, the exact ghost-lock the escrow kills). Ceremony must `naked_rule::add` on the character policy at next publish
- 2026-08-12 · CHAT SCOPES (owner): world chat = one channel per WORLD (not zone); party chat + whispers are network-wide; a seated fighter never spectates
- 2026-08-12 · THE OFF-CHAIN MESH LAW (owner): the server BROADCASTS only what never touched the chain — movements, chat, live fight-turn intents; an on-chain fact (an equip, a join) is never re-broadcast by a server — it reaches other players by FORWARDING the indexer's evt:* stream (a visible player's own evt:character channel, watched per the visibility ledger). Visible equipment = hat/cloak/pet/title ONLY (the rest is fight-internal HP math). Fight-turn intents relay after validation — TODO(sim): legality checked against the simulation package once it exists
- 2026-08-12 · CLUSTER SHAPE (owner, legacy law): pods are cattle — each writes ONE `server:<uuid>` redis key (online count, 20s TTL, 5s refresh; the one sanctioned ephemeral write) and any pod count sums the live keys; `packet/server_info` pushes the sum on a flat 5s cadence, decorrelated from user activity. - 2026-08-12 · THE PURE REDUCER LAW (owner — server harness constitution, the legacy player.js pattern verbatim): a reducer's ONLY role is folding actions into state — `(state, action) => state`, no context, no I/O, ever. Every effect lives in OBSERVERS wired on the context's local `events` emitter — after each fold the loop emits the action's type and `STATE_UPDATED(state, previous)`, exactly the legacy loop; observe() returns nothing, teardown rides the abort `signal`. Input needing validation is caught on its action event, validated (async allowed), and re-enters as an internal `action/*` dispatch; the reducer folds it; observers act on the STATE_UPDATED delta, never the packet arrival. Input needing no validation may fold directly. A module that never touches state (admin answers) is a pure observer with no reducer. The redis mesh keeps the `pubsub` name — `events` belongs to the loop emitter, as in legacy
