# AresRPG active decisions

`ARCHITECTURE.md` owns the current system model. This file keeps active domain decisions whose motive
must remain durable. It contains neutral technical prose only: no transcripts, personal quotes,
personal attribution, or conversational incident history. Search the domain being changed; do not
treat the file as a second architecture. One line owns each decision. When a decision changes, amend or
delete its row; superseded decisions never remain.

## Patterns — how to think here

- 2026-09-02 · JOB INGREDIENT LINKS FOLLOW THE NEXT PLAYER ACTION: clicking a raw, gathered, or dropped ingredient opens that item in the encyclopedia; clicking an intermediary resource selects its effective crafting profession and opens that recipe inside the Character Jobs detail, where the existing affordability, level, and transaction gates remain authoritative. The compiled catalog's resource kind and effective recipe job decide the destination; UI labels never infer it.
- 2026-09-01 · MASTERY IS ONE ADDRESS-WIDE EPOCH QUEST: a sender chooses any WorldContent that one free owned Character can enter; terminal Sui randomness assigns one unique city dungeon from that world, and the world's entry level snapshots a 1/2/3/4/5-point reward at levels 1/51/101/151/200. Any owned winner may validate it only through a final-room Fight created in the assigned world strictly after the quest, so a parked victory cannot be claimed retroactively. One missed Sui epoch expires the spendable score; every mutation normalizes it. Derived living MasteryOffer objects reference statless item templates, subtract their authored enabled cost, and mint one item into the personal kiosk. Loot boxes retain their separate open/claim randomness; an empty loot-box table fails publication validation until its rewards are authored. Owner receipts reconcile live writes; the indexer/server provide only the reconnect snapshot and current indexed epoch.

- 2026-08-31 · MOVE PACKAGES FOLLOW ONE MANIFEST AND ONE SIZE LIMIT: root `move-packages.json` is the public deployment graph for math, control, combat, seed, and core. Math owns pure values; control owns administrative authority; combat owns only deterministic authority-free fight state; seed owns living content objects; core owns UID, key, custody, transfer, event, clock, entropy-source, and transaction-context authority. CI, SDK publication, pins, coverage, and release tooling derive these exact five slots. Every package has the same 96,000-byte raw-bytecode ceiling, preserving metadata headroom below Sui's 102,400-byte object limit; package-specific budgets and compressed atom names are forbidden.
- 2026-08-31 · FIRST-OPEN GUIDANCE IS ONE DEVICE-LOCAL COACH-MARK SYSTEM: the creation welcome remains the empty-roster entry, while one global host derives the next unseen tutorial from loaded page and fight truth, highlights stable semantic DOM anchors or the engine-projected active character, and blocks underlying input until that sequence is finished or skipped. World guidance is one ordered sequence; an owned first fight gets one centered explanation; each character detail tab is independently first-open and never causes automatic route changes that could discard staged edits. Completed tutorial identities persist in settings, malformed identities are discarded, and Settings can reset the set for replay. Every player-facing step ships in all six locales.
- 2026-08-31 · WORLD CHARACTERS USE SHARED-POSE SKINNED BATCHES: nearby non-controlled characters are engine presentation instances grouped by body/hair/equipment topology, locomotion clip, and active/frozen state; character count changes instance buffers, not skeleton or mixer count. Three per-instance TSL colors replace crowd CanvasTexture/material clones, while rigid hair and worn models reuse the batch pose through their shared attachment bone. Batches cap at 256 instances and split mechanically. The selected world character, tactical fighters, invisible actors, mobs, and pets retain the individual entity lifecycle because interaction beats and independent animation are worth their bounded cost. The stable shared-pose WebGPU path is the production law; unversioned individual-compute example code is not vendored.
- 2026-08-30 · AN OWNER TAG PREPARES PRODUCTION; ACTIVATION IS MANUAL: `edge` is the only persistent branch and deploys every green commit only to `edge.aresrpg.world`; from clean current `edge`, the root `bun pm version` lifecycle creates one signed version commit and tag, pushes both with `--follow-tags`, and tag CI stages production without moving its domains. When Move changed, receipt-derived hardcoded pins land before versioning so the tagged frontend and backend share one chain address book. Trusted Actions builds only changed server/indexer inputs into public `ghcr.io/aresrpg/*` tags with provenance; an unchanged service gets a registry-side release tag pointing at its previous digest, without rebuilding. One retained manifest records the tag SHA, package lineages, resolved image versions/digests, and staged Vercel URL. After content reconciliation and Helmfile sync, a separate owner-only manual workflow verifies that manifest and promotes the exact Vercel build without rebuilding.
- 2026-08-30 · A PROJECTION LINEAGE IS GAME ORIGINAL + SEED ORIGINAL + RECOVERY EPOCH: ordinary image/latest-package changes preserve the composite identity, PVC, and watermark; changing either original package automatically renders a fresh StatefulSet and disposable store so the replay cannot skip a newly published package's early state. The indexer binds both originals inside the store. `projectionEpoch` exists only for an explicit testnet recovery flush when the package originals did not change; non-testnet forced flushes are forbidden. The release ceremony always runs the same Helmfile sync—the rendered identity decides roll versus repin.
- 2026-08-29 · PINNED ARESRPG PTBS ANNOUNCE THEMSELVES FIRST: every ordinary SDK-created PTB with a current math-package pin starts with the object-free `aresrpg::aresrpg` call; raw SUI transfers and the complete deployment lifecycle remain bare because it runs across stale and changing package pins. Random-consuming game doors stay terminal, and the header emits no event or state.
- 2026-08-29 · ADMIN OVERVIEW IS KPI-FIRST, WIDTH-FIRST, AND SECTION-CACHED: the retained Hytale dashboard hierarchy is the design reference—compact primary metric cards lead, treasury actions follow, then short time-series panels use the available width. Charts stay two per row on wide screens: revenue beside successful game transactions, player activity beside online presence, and unique-address beside character history; they stack only when width demands it. Transaction volume counts each successful non-deployment PTB touching any game-package lineage version once; its independently ranged chart reads replay-safe per-checkpoint numeric bucket fields, never command counts or digest sets, while one permanent checkpoint hash owns the all-time total. Net game gas includes successful and failed game attempts but excludes raw publish, package upgrade, seed-package writes, and core bootstrap/pause/resume calls; exact 24-hour and permanent MIST totals share that replay-safe checkpoint identity. Deployment-only senders never enter active-player or first-seen-address projection; genuine later gameplay from the same wallet still counts. Charts carry no numeric footer because KPI cards already own their summary totals; the treasury strip alone retains the two live royalty balances beside treasury and the claim action. Overview scrolls vertically instead of stretching charts to consume viewport height. Time selectors wrap without scrollbars, and responsive SVG plots never contain text that `preserveAspectRatio="none"` can distort; axis values remain ordinary HTML. Discrete counts use integral axes and hover values, every hover shows the bucket's local date and time, and online history presents peak concurrency only beside the live online KPI. Each section caches all five range responses for the session; a cache hit switches synchronously without a request, while a miss loads only that section and never unmounts the rest of the overview.
- 2026-08-28 · CRUSH PRESENTATION IS AN INVENTORY SUBSET: confirmation becomes one non-dismissible animated-item modal from submission through deterministic claim redemption and projected result; the inventory never flashes back between phases. Crush redemption performs one explicit object hydration and fails once if the selected read node has not converged; SDK polling and transaction retries are forbidden. The durable claim retries through the frontend's normal later sweep. The result carries exact projection-touched `ItemRow`s and renders canonical compact inventory cells without misleading level badges; hovering a rune opens the shared detailed tooltip, whose rune identity derives `+amount stat`. It never invents a yield view model, reward card, or alternate item display. An existing rune stack therefore shows its live post-crush total, because the projected inventory remains the one item fact.
- 2026-08-28 · CRAFTING CHARACTER LOCK IS ONE NULLABLE DEVICE PREFERENCE: `always_craft_from_character_id` is null when disabled and otherwise names one owned character; no parallel enabled flag or Jobs-local selection exists. Session remains the sole owner of selected-character state: opening or directly reloading the Jobs route selects the configured character, other character tabs stay locked there, and leaving Jobs restores ordinary selection. An authoritative roster that no longer contains the configured character clears the preference before any craft can target a fallback character.
- 2026-08-28 · A KOLIZEUM JOIN IS AN EXPLICIT WAGER REVIEW: clicking a lobby row only selects it; full Join Side A/B controls live with the selected rosters. Either control snapshots the acting character, exact MIST stake, and side into a confirmation that spells out `wager X SUI and join Side X`; only its confirm action dispatches those same identities. The join input carries the reviewed character ID instead of rereading the selected tab, so a tab switch cannot silently change who signs the wager.
- 2026-08-28 · CHAT REFERENCES ARE STRUCTURED SEND-TIME SNAPSHOTS: `%pos%` resolves the speaking character's live world/position into a clickable run target, and `%xp%` resolves its class, level, and percentage to next level; the send edge expands once, then world, party, whisper, and local echo carry the same validated typed parts rather than scraping display markup. Chat interactions use left click only, and the one viewport-global player-menu host is never gated by world, fight, dungeon, or page presentation. Those parts are untrusted presentation claims—the existing movement proof still gates running, and the tooltip accepts only an exact original-package Item. Inventory `Link in chat` appends exact object identities to the one reducer-owned draft, while recipients fetch that Item and its rolled-stat field through the SDK on first hover. One authenticated-session promise LRU retains 20 successful or in-flight reads and evicts failures, so pointer movement never duplicates a request while transient read errors remain recoverable. The tooltip shows an honest loading state, then the shared read-only `ItemDetailView`.
- 2026-08-28 · RUN-TO IS ONE GENERIC CLIENT DOMAIN: Party-member targets enter by one SDK checkpoint snapshot; chat position targets enter already resolved. One reducer owns request, target, selection cancellation, Party-membership cancellation, and flat-mode activation; the engine consumes only its final position. Party member rows show their target distance, while every static-position run shows one global distance/progress bar below both the compass and zone-discovery card, regardless of Party state. Neither source adds Move, server, or protocol movement authority—the existing speed gate and chain travel proof remain the bouncers.
- 2026-08-28 · TRANSACTION INTENTS ARE SYNCHRONOUSLY SINGLE-FLIGHT: a disabled React button is presentation, never the lock—React may not render before another click. Every direct component transaction enters one tab-wide closure-backed player-gesture lane before creating its promise; it survives component unmounts and page switches. Reducer-owned domains acquire their own effect-boundary key/set before calling the SDK. Failure releases the lock. Receipt success releases it only when that receipt synchronously folds away the triggering state; projection-owned Party, dungeon, Kolizeum, fight, and Trade operations remain locked until their exact authoritative row arrives. A source census test pins every current transaction owner and its guard.
- 2026-08-27 · PVP TRAP PLACEMENT IS TEAM-PRIVATE PRESENTATION, NOT CHAIN SECRECY: when opposing teams both contain players, a trap cast and its placement cue play only for viewers on the caster's team; opponents and spectators receive no target-cell highlight or placement VFX. PvM keeps ordinary trap presentation, and a triggered trap reveals normally to every viewer. The fully on-chain checkpoint and courtesy action wire cannot provide cryptographic secrecy, so this rule governs honest-client presentation only.
- 2026-08-27 · STREAMED MOB WITNESSES RECONSTRUCT THE MISSING NORMAL BOUNDARY: the submitting client applies End Turn before its receipt witnesses, but peers receive only the ordered `TurnSeedUsed` stream. An unexpected streamed witness reconstructs `start` from placement or `end_turn` from the current active seat before applying the witness; it never substitutes `crank`, whose stall timeout rejects an ordinary player boundary and skips the intervening mob turn card, highlight, and playback for peers.

- 2026-08-27 · PARTY FOLLOW IS SESSION AUTOMATION, NOT GAME AUTHORITY: one persisted settings boolean enables follow for the selected character's Party; Party state never copies that preference or stores a stale Party id. While enabled on an owned Party leader, client-only follow advances every eligible same-world owned member in straight X/Z space at 10.5 blocks/s and publishes the existing per-character position intent; Y follows the leader sample without terrain/pathfinding. Followers occupy distinct two-block slots in one world-X line beside the leader instead of stacking; selecting a follower temporarily removes only that controlled character from automation, while the preference and other followers persist and resume when the leader is reselected. One external owned-position feed combines manual and followed movement, locally renders every other same-world owned character that the server deliberately does not echo, and lets selection resume from the last live point; the same per-character IndexedDB writer persists both kinds of movement, while follow distance remains external and never enters Zustand. A leader entering combat clears only the controlled overworld pose: follow retains that leader's last owned world point as its target, and an unavailable target is unknown rather than zero metres. Both external feeds and their pending/saved resume rows clear whenever a ready server link is lost, and the rendered character returns to its chain checkpoint, because a new connection reconstructs presence from chain anchors and replaying the old local point would be a speed-gate teleport. A left-click on an eligible external Party row opens the one shared player context menu; its run-to action performs the sole direct authenticated checkpoint read, snapshots that member's current-world checkpoint once, refuses another world, enables flat mode, warns that the point is not live, and straight-runs the selected character until arrival or manual cancellation. If that selected character is the followed owned leader, ordinary follow carries the other eligible owned members without a second automation path. The server speed gate and Move travel proof remain authoritative. In a leader-created ordinary overworld PvM placement, each eligible follower joins independently as soon as it reaches three blocks from its slot; distant followers keep approaching and may join later only while placement and side capacity remain open. Locally reserved seats prevent duplicate or over-capacity join transactions; follow never automates readying or combat.

- 2026-08-27 · COVERAGE IS A NATIVE TEST PROPERTY, NOT A DASHBOARD SCORE: every language/package lane targets more than 80%; today's enforceable floors are stepping stones that rise in the same change as meaningful behavioral coverage gains and never fall. The canonical Bun suite covers all package and repository tests in one process, excludes test files and generated sources, and feeds native LCOV into a 60% line / 75% function aggregate. The Rust indexer runs pinned cargo-llvm-cov 0.9.0 over every source module with a 65% aggregate line floor. Sui native coverage includes every authored module with package floors control 60%, seed 30%, math 30%, combat 25%, and game 25%; zero-coverage data/access modules remain visible. Bun's built-in threshold is not used because it applies per file and would reward a giant ignore list for platform/render boundaries. CI owns each language in its existing job; pre-commit routes only staged implementation languages, while `bun run coverage:all` runs the whole set. Floors guard untested deletion and new paths; they are not permission to write metric-only tests, and red-first behavioral proof remains the real quality law.
- 2026-08-27 · COMPLEXITY IS A DOWNWARD-ONLY DISTRIBUTION, NOT A FUNCTION-SPLITTING SCORE: handwritten JS/TS prefers cognitive complexity ≤10 and cyclomatic complexity ≤8; new functions never exceed 15/12, nesting never exceeds 4, and every inherited soft hotspot is pinned by semantic function owner and exact descending score distribution. ESLint runs the official SonarJS cognitive measure plus the local cyclomatic twin in both staged-file and CI lint. A changed distribution fails until `bun run complexity:baseline` proves that no score rose and no new hard breach appeared; reductions ratchet immediately. Extraction that merely moves the same decisions between helpers is still complexity and remains a review refusal, because no per-function metric can prove the data model improved.
- 2026-08-26 · SOCIAL DOMAINS SHARE AUTHORITY, NOT STATE: Friends, Party, and Trade keep separate reducers and SDK action hands; authentication/session owns none of their rows. The existing `FriendRegistry` stores one boolean membership marker per character, so one character cannot inhabit two parties without duplicating which Party owns it. FriendList, Party, and Trade object writes are their realtime invalidation facts; existing shared-object actions return certified completion only, while one bounded latest-wins projection owns each mutable row. The first invitation creates the Party with that pending target atomically; later invitations mutate the existing Party. Any accepted member may invite; leadership remains the destructive authority for rescind, kick, and disband. Both invitation doors consult `FriendRegistry` and refuse a target already in any Party, while presentation hides legacy stale invitations for a currently grouped character; an unsolicited invite never makes its target sign or pay gas to decline. Invitation authority proves the same acting Character from its kiosk or from its sender-controlled Fight seat, with the expected character id sealing stale seat data; custody changes no social permission. Every invite button dispatches the same input, and every selected target—including another character in the same wallet—answers through the same projected Accept/Decline card and custody-proven door. No empty-Party creation door, synthetic receipt Party projection, or owned-character acceptance shortcut remains. Leave/disband stays optimistically hidden and pending through receipt success until `packet/party: null`, so a dead party id can never be reused in the projection gap. Friends remain a directed whitelist, Party remains character-keyed, and Trade remains version-pinned escrow whose public claim doors never expose the counterparty's transferable PurchaseCap.
- 2026-08-26 · EVERY CERTIFIED TRANSACTION SPEAKS ONCE: the SDK execute boundary permanently logs one pink `tx` row with digest and net SUI cost for every submitted receipt; its SUI breakdown is computation + storage − rebate, with success/failure retained as data rather than label decoration. Preflight refusals have no digest or gas and therefore never impersonate a sent transaction. Individual action modules never add their own transaction logs.
- 2026-08-26 · LOCAL READS BIND THE BRANCH PIN SET: every branch owns one deployment through root `pins.json`; no alternate local pin overlay exists. A new development branch whose pins still match its merge-base deployment republishes independent originals before any upgrade; private branch memory then refuses lineage conflicts. Local indexer/server orchestration receives package originals/latest from that file, replaces FalkorDB whenever the game or seed original changes, and preserves its watermark only across compatible upgrades of the same originals. The frontend imports the same root pins. The server's five-second cached health packet exposes lag during catch-up; connected clients block without a dismiss door while lag is unknown or above 300 checkpoints, retain a rolling 12-sample progress/rate window, show a live countdown ETA to the playable window, and unlock automatically. Hand-written `docker run` and retained cross-lineage graphs remain forbidden.
- 2026-08-26 · FIGHT BOARDS CUT THROUGH WORLD WATER: a mounted tactical board extends the existing peephole through the world water surface and suppresses camera immersion for the board lifetime; surrounding water remains rendered, and unmounting restores normal water without inventing a surfacing splash.
- 2026-08-25 · DISCOVERY COMPLETES WITH ITS POPULATION: a zone-search success waits for both the projected `ZoneRow` and its seed-derived `packet/zone_spawns`; the retained 2.5-second center reveal reports individual mob members and total resource nodes—never a generic toast. Cities and dungeon entrances derive directly from authored world content and never enter the zone discovery wire. The transaction receipt alone and the zone row alone cannot produce the population summary, and the client never reruns zone RNG.
- 2026-08-25 · LEVEL-UP KEEPS THE LOCKED RADIANT CEREMONY: the character level-up card is the exact retained `deprecated/game/screens/hud/LevelUp.jsx` ember/gold ceremony adapted to current chain data—filigree, seven sparks, large foil level, class/title, point grants, spell/world unlock rows, and persistent Allocate/Later choices. Once terminal presentation drains, level-up layers above the retained fight result; acknowledging it reveals that result beneath instead of deleting both. `Allocate points` also selects the leveled character and deep-links `/characters/stats`.
- 2026-08-25 · EFFECT DURATION INCLUDES THE CURRENT TURN: timed fighter rows decrement at the affected fighter's turn end. A two-turn self-buff is active and displayed as `2` during the casting turn, `1` during the next turn, then expires—never two additional turns. Move and the local fight twin share this lifecycle. Invisibility expiry projects an ordered visibility edge before the following turn cue, so targeting truth and the rendered body become visible together.
- 2026-08-25 · THE GATHER ROOT IS A VISIBLE CLIENT ACTION: `gather_time_ms` remains the chain-authored 12s→2s post-harvest root, mirrored once in immutable. The client starts a centered rounded HUD progress panel and repeating self-buff pose at the gather press, locks movement and suppresses another resource target, then replaces its estimate with the streamed character checkpoint deadline. Receipt latency may extend the conservative fallback but can never unlock before chain truth. The receipt records exact quantity immediately, but its success toast and gather sound wait for the effective deadline; the toast names quantity and item with its canonical compact icon. A protector verdict ends the gathering presentation immediately, keeps movement locked, and automatically composes `resolve_ambush` from receipt-known content while a passive status replaces the old extra key press. Protector resolution returns its receipt-certified `FightCreated` ID and immediately arms `fight/watch`, so mounting never depends on having remained connected for the original event; the roster projection still reconciles authoritative ambush details afterward. Every changed chain checkpoint re-targets the visual body before another pose can be persisted or published, so refreshing a future-dated ambush root cannot trigger the server speed gate. Abort 305 during the ordinary gather interval is a client-gating bug, not a distance error. Every streamed `res_taken[pack.index]` increment reduces the pack’s surviving low-ordinal marker prefix by one, so consumption removes one outer world node and zero removes the whole pack.
- 2026-08-25 · GATHERABLES LOOK LIKE THEIR IDENTITY, NOT THEIR JOB: resource batching keys by `item_type`; job and tier remain fallback presentation inputs, never the whole art direction. Mushroom gatherables use grounded 3D voxel colonies with authored identity palettes—Ivory Shrooms have warm stems and bright ivory caps—while retaining one instanced draw per authored gatherable.
- 2026-08-25 · FIGHT SWORDS ADVERTISE FAR, INTERACT NEAR: every tracked sword floats the shared ornate nametag within the same 50-block range as mob packs, while only the nearest sword within four blocks exposes and accepts `F`. The zone marker stays slim; opening the join/spectate modal arms its existing fight watch, and both placement and active phases render the hydrated checkpoint’s full two-side roster with mob portrait or character placeholder, resolved name, and level—never count-only cards or guessed identities.
- 2026-08-25 · TURN INTRO CARDS FOLLOW PLAYED PRESENTATION: each presented active-fighter transition briefly slides one pointer-transparent, portrait-first identity card from the canvas edge; the authored mob portrait or neutral character silhouette owns most of its large Dofus-like frame beside localized name and level. The composition is only the portrait plus two top-aligned floating text bands—no card-wide black backing panel, polygon, or footer stripe. Only a played `turn_switched` cue may create the card; canonical checkpoint fallback is a second trigger and is forbidden. The cue carries structural `fight + round + seat` identity, so receipt prediction and indexed replay reduce to the same retained announcement and cannot remount its CSS animation.
- 2026-08-25 · FIGHT TIMERS OFFER ACTIONS, THEY NEVER TAKE THEM: the placement deadline reveals an explicit Force Start control; it never submits `start` autonomously. A Kolizeum fight is born with an unarmed zero placement clock; reaching its full authored format arms a fresh deadline, dropping below full during placement disarms it, and refilling starts a new full window. Ready may still be recorded before full, but an unarmed clock can never authorize Force Start. Ordinary and dungeon Ready keeps one terminal Random door whose current shared-state read atomically starts when this transaction supplies the final missing ready; it never trusts a stale client `and_start` guess. Its per-fight latch stays disabled through receipt completion and stale placement rows until start or explicit refusal. When one wallet owns multiple ordinary-fight seats, Ready All composes every non-final Ready before that one terminal final Ready in a single PTB; a non-final door that unexpectedly becomes final aborts the whole batch safely. End Turn remains queued through the three-second chain floor. An abort 1724 raised while transaction resolution is still pre-submission cancels only the pending boundary, preserves the movement/cast draft, and retries after a bounded clock-skew backoff; an executed failure never retries. Turn identity includes round, queue pointer, and timestamp because adjacent turns may share one chain millisecond. A mob card highlights for one second before its action starts, then retains the turn through at least two seconds of action time before the next card; a partial streamed turn witness keeps that presented card, visual checkpoint, and input lock alive until the authoritative resting checkpoint arrives, so an intermediate canonical snapshot can never roll movement back.
- 2026-08-25 · MOB AI AIMS FROM EFFECT TARGET INTENT: healing still selects the most wounded teammate, caster-only books select self, and every normal/critical row restricted to allies selects the nearest living teammate with self fallback; only mixed or hostile books use the nearest enemy anchor. Move and the fight simulator derive this from target filters, never spell names or effect stat.
- 2026-08-25 · MOB SPELLS CLONE WITHIN THE LIVE FAMILY DRAFT: the mob spell sheet offers one-click clones of complete, not-yet-owned spell names from other mobs sharing the authored family; it reads the current `mobs.json` draft rather than the boot catalog, deep-copies the one-level spell, and still respects the five-spell kit cap.
- 2026-08-25 · MOB LOOT CHANCE RESOLVES WITH MOB LEVEL: authored `chance_bp` is the midpoint of a separate 80%→120% minimum-to-maximum mob-level band, capped at 100%; mob birth snapshots that resolved chance, quantities remain authored, and settlement applies average winning-team Chance afterward.
- 2026-08-25 · ITEM DETAIL ART IS HD BY CONSTRUCTION: `ItemDetailView` resolves its own `item_type` through the HD display route; compact lists and fight-result loot resolve the canonical thumbnail directly, so callers cannot silently downgrade a detail sheet.
- 2026-08-25 · MOB SPELLS HAVE ONE LEVEL, PLAYER SPELLS HAVE SIX: an embedded mob spell authors and stores exactly one `SpellLevel`; mob birth scales its safe numeric rows through the mob’s 60–160% resolved power band and never selects a spell rank. A positive authored effect always remains at least one after integer scaling—low-level buffs, removals, shields, and damage can weaken but never become zero-value rows. Player `SpellTemplate` remains a separate six-level contract. New empty mob spells stay local until an effect exists, and mob spell editor identity is its stable list index—not its name while typing.
- 2026-08-30 · MOB AP IS A REAL ACTION BUDGET: a mob brain repeats its priority scan after every successful cast and may interleave movement while MP remains, then keeps casting while AP, cooldowns, `casts_per_turn`, and `casts_per_target` allow. A high-grade mob with 8 AP may therefore cast an uncapped 4-AP spell twice; `casts_per_turn: 1` deliberately prevents the second cast. Mob spells must cost at least 1 AP so the deterministic loop always terminates. Move and the TypeScript twin enforce and test the same rule.
- 2026-08-30 · NAUVIS MOB FAMILIES HAVE DISTINCT JOBS: ants are seven-MP colony supports whose all-map link redirects allied damage to the casting ant, then poison in Air or Fire; Aragnes trade HP for elemental webs, pulls, haste, and poison; Crab is a slow shield/reflect locker; Crowani are buffing crocodile warriors; Moka is a simple melee skeleton while Moyumi is a ranged Range-remover; Wild Boar is a tanky four-MP plains bruiser whose Earth attacks repeatedly push its target; Misunami is the healing, pulling, life-stealing Misui archi. Araknomath is the exception boss at 4× reference HP and exactly 3× XP: linked ants create an add priority, Cocoon creates a shield/reflect timing window, Prime Web forces movement, Factor Line and Remainder Slam punish positioning, and Final Proof scales with missing boss life.
- 2026-08-25 · REFERENCE COHORTS USE COMPARABLE COMBAT ROLES: Ares resource protectors use ordinary same-level Dofus monsters as their balance cohort. The panel names requested role, actual cohort, and donor level range.

Authored values may move inside these family envelopes; tests enforce the archetype and reference ratios rather than pinning individual rows.
- 2026-08-24 · MOB AUTHORING SHOWS DERIVED RANGE TRUTH: the content editor projects min/max combat values through the same fight helpers as mob birth—AP/MP use their 100–130% pool law, all other power uses 60–160%. Beside Agility it shows single-locker tackle versus a 200-Agility runner and full-pool AP/MP dodge versus a 200-Wisdom attacker; tooltips state the live multi-locker, attacker-Wisdom, and remaining-point dependencies.
- 2026-08-24 · DEFAULT EFFECT VALUES STAY EDITABLE: editable optional-duration effects show `Instant` at zero turns and every effect shows its chance including 100%; changing kind resets hard-instant mechanics to zero turns and initializes hard-timed mechanics to one. Direct damage, displacement, teleport/swap, trap placement, and dispel never pretend duration is legal.
- 2026-08-24 · POINT IS AN EDITABLE AREA, NOT THE ABSENCE OF A CONTROL: every editable spell effect shows its current area shape, including `Point`; clicking that chip selects Circle/Cross/Line/T-bar/Ring/All-map/Cone/Podium/Blob and its size. Read-only point effects remain visually quiet.

One speed-driven heel/toe-plus-friction exciter feeds the material response: modal resonances for solids, stochastic particles only for aggregates, and descending bubbles for liquid. When synthesis lacks ecological validity, a small proven or CC0 recorded impact set may replace that preset's exciter from the flat `seed/sounds/` corpus, decoded once and provenance-recorded; cadence and material selection remain shared. Footsteps add no parallel block-name taxonomy, timer cadence, fight-board duplication, or per-frame audio graph.
- Take facts from the context, never as parameters: the sender lives in `ctx` — a parameter that repeats what the context knows is a redundancy that can lie
- Flatten until forced: no wrapper struct for three colours, no subfolder for one package, no explicit dependency the toolchain injects itself — hierarchy must earn its existence
- Denormalize for the reader, with exactly ONE writer: `level` sits on the character so wallets can read it; only the progression door writes it, in the same transaction as the xp it derives from
- The module boundary is the security boundary: data modules own shape and invariants behind public(package) doors; gate modules own policy (names, prices, whitelists); consumers compose doors
- Gas outranks storage purity: players pay computation forever, while storage deposits refund on deletion — snapshot sealed data into short-lived objects freely, never recompute per action what a stored copy answers; derivation is for LIVE state that can drift
- Latest of everything, no duplicates: lean on toolchain defaults over manual pins; a pin is a scar, not a habit
- The pattern library is the aresrpg-legacy repository (the original testnet game — lean, proven; the frozen move-old/rpc-old trees live in git history) · before designing any mechanism, check how legacy solved it and carry the pattern, not the code
- PTB-safe stays OUT of the modules: anything a frontend PTB can do safely never pollutes Move — a Move signature must ask only for what it genuinely needs. Personal-kiosk custody is a publish-time transfer-policy rule (`personal_kiosk_rule` + `kiosk_lock_rule`), which natively forbids an item leaving for a non-personal kiosk; therefore doors take a bare `&KioskOwnerCap` (provably a personal kiosk's soulbound cap) and `PersonalKioskCap`/`personal_kiosk::borrow` live only in PTBs — threading the wrapper through Move buys zero extra safety
- PERSONAL KIOSK CAP CUSTODY: the character packet owns kiosk and PersonalKioskCap identity, never its mutable object version. The authenticated session loads stable kiosk identity once and overlays receipt-fresh refs. Every custody domain uses one kiosk runner; only a proven pre-submission stale-cap failure performs one fresh lookup and rebuild. A transaction carrying a certified digest never retries.

## Decisions

- 2026-08-23 · LIVING CONTENT STAYS OUT OF LOGIC: the five-package graph is math (pure values), control (AdminCap), combat (authority-free fight machine), seed (Registry-rooted content objects), and core (gameplay objects and authority). Mutability lives in objects behind cap-gated doors, never in package logic. Core reads content through accessors only. Copy-at-boundary protects historical fights and unique items: mob kits snapshot at engage, boards copy into Fight creation, and unstackable rolls copy at mint. Stackable consumables deliberately read one live template effect so merged units cannot diverge. Removing content means removing its live references; claimed derived identities are never recreated as another fact.
- 2026-08-23 · FREEZE_FOREVER IS THE ENDGAME SEAL: ONE irreversible cold-key-only door sets `frozen` on the seed registry root; every content door asserts it through `registry::bump`/`uid_mut`, and the supply doors will assert the same flag through the registry's cap-gated claim/bump seam. No unsetter exists; a daily temp cap can never pull it. The mechanism ships and is tested from v1.
- 2026-08-23 · CAST IS THE SANCTIONED LIVE-READ: player casts read `&SpellTemplate` live — a full spellbook is too big to snapshot into the Fighter and the layout change would drag the indexer. A mid-fight spell rebalance lands on the next cast, abort-clean, twin-visible via the registry revision; the rebalance composer refuses spell/mob writes while wagered kolizeum lobbies are open (money guard — Move-side is impossible, seed cannot see core's lobbies).
- 2026-08-23 · OWNED-ITEM SPLIT: unstackable gear keeps its mint-time rolled stats and damage lines forever; EVERYTHING template-shaped on a stackable reads LIVE — the consumable effect, pet-food eligibility, forgemagie ceiling, and loot-box pools. A stackable's only owned fact is its amount.
- 2026-08-23 · FIGHT BOARDS ARE AUTHORED CONTENT: `seed/content/fight_boards.json` is the ONE authoring home — the validator proves full connectivity offline, `combat_grid::grid_spec` holds the cheap on-chain sanity floor, the catalog stores one dynamic field per board (dense indexes by construction, add/replace, never remove), every creation door picks `boards[seed % len]` and COPIES into the Fight, and the simulator reads the same JSON. On-chain generation is dead (test-only fixture machinery now) — it was 70–89% of fight-creation gas with a seed-dependent 16× cost tail.
- 2026-08-23 · THE FIGHT GAS BASIS IS 0.02 SUI: the reference 12-turn/3-mob PvM fight must net under 0.02 SUI; real fights keep unlimited turns and up to 6 mobs, and no lever may cap either for gas. Runtime spell targeting is FIGHTER-FIRST: each effect checks at most the twelve fighters once through one constant-time zone rank, preserving historical target order; board-cell enumeration is test/presentation machinery and never a resolver input. Constructors cap an effect branch at eight rows, area size at ten, AP cost above zero, and conservative mob work at ten row-casts per turn. Runtime-shaped White Ant and general-wave gas tests ratchet these bounds. The last mile is the close door's storage rebate (participant-only — an open door lets bots farm player-funded deposits) and the bounded mob AI; the irreducible floor is Sui's ~0.0016 SUI per transaction × one transaction per player turn.
- 2026-08-22 · THE CHALLENGE IS THE INVITATION: `challenge_duel` names the target and reserves side B for that character (`ACCESS_INVITED`), so the Fight object carries the invitation and the challenged client reads it from the streamed fight row. Sword discovery remains public. During placement the modal shows both teams and lets chain access enable each join control; after start it offers spectate. A challenge costs gas before consent, and a refused duel leaves the challenger on their visible board to leave.

- 2026-08-22 · THE GATE IS DRESSING, THE CHAIN IS THE BOUNCER: every world's portal renders unconditionally at client 0;0 as engine dressing (one TSL disc, sunk into the terrain, exits with the flatten's water phase) — no per-world config exists to drift; the approach prompt is PROXIMITY-gated, never cursor-hover. The travel surface is a small grid of real landscape cards whose generated art is presentation-only; authored worlds still own identity, biomes and entry level, and the chain reasserts every lock. Arrival folds only from `WorldJoined`, and the refreshed roster anchor remounts the destination surroundings.
- 2026-08-21 · ONE RESOLVER SIMULATION, ONE FIXED GAS BUDGET, GAS COINS ARE THE RESOLVER'S: the official Core resolver selects gas and simulates the unsigned transaction once before the wallet opens; the SDK must not simulate those resolved bytes a second time. A successful resolution signs once and submits once. `GAS_BUDGET_MIST` is pinned at 0.2 SUI, so no estimation simulation is needed. The SDK NEVER names the gas coin: which coin — or whether a coin exists at all, since an address may hold its SUI as an address balance instead of `Coin` objects — is the Sui resolver's answer, and pinning one receipt-fresh ref with no fallback is what told a wallet holding 1000 SUI it was out of gas. A resolver simulation refused for gas is OUR budget, not the player's wallet: it raises its own toast and must never read like an empty balance.
- 2026-08-21 · ADMIN OVERVIEW READS ARE WALLET-FREE, THE TREASURY IS A NAME: every chain-readable fact on the admin page (treasury balance, policy royalty balances) loads immediately through the SDK's read-only client—the one sanctioned direct Sui GraphQL path for this surface—and a browser wallet connection exists only to claim royalties. The treasury address is never hardcoded off-chain: it resolves from SuiNS (`treasury@aresrpg`) lazily when the admin page loads. Off-chain metrics wait for their server route, never a chain workaround.
- 2026-08-26 · SOCKET QUARANTINE ADMITS ONLY THE PROOF: WebSocket `OPEN` is transport state, not authentication. Until `packet/connection_accepted` arrives, the public link door returns false for every application packet; only the internal response to that socket's signature challenge may send. Navigation, market observation, chat, presence, or any other UI state change during verification therefore cannot become `INVALID_PACKET` and falsely clear a valid wallet as `could not verify`
- 2026-08-20 · ONE SEAT PER ACCOUNT, THE EVICTED WINDOW STAYS DOWN: the server keeps one socket per address (same-pod `REPLACED`, cross-pod `ALREADY_CONNECTED`); the kicked client parks the link in a terminal red state with a `connected from another place` modal and NEVER auto-reconnects — a retry would only steal the seat back and ping-pong both windows. Reconnecting is an explicit human action.
- 2026-08-20 · THE SDK IS WRITE-FIRST, THE WIRE IS SNAPSHOT-THEN-DELTA: the SDK reads chain state only for transaction-building facts (object refs/versions, balances) and two explicit one-shot presentation exceptions: Party run-to snapshots one external character checkpoint in parallel, while a linked chat Item tooltip reads that exact original-package object plus its rolled-stat field through a 20-entry authenticated-session success/in-flight LRU. Everything else a player sees comes from indexing through server packets; the inventory loads ONCE at boot and then moves only by per-item add/update packets (packet/item_updated, the bounded packet/items_request for receipt-named ids) — never a bulk re-push. Pending claims settle SILENTLY (modules/claims.ts) with zero claim UI; an empty gas tank raises the one blocking top-up modal.
- 2026-08-20 · CONTENT EDITION LIVES ON /DEMO; RELEASE WRITES HAVE NO BROWSER PATH: seed content, dungeons, and biome editors belong to the local `/demo` composition lab, where the live engine renders the edited recipe. The in-game admin page keeps read-only analytics, sales history, and royalty-wallet actions only. Package publication, content reconciliation, pause/resume, and permanent freeze belong to the private release ceremony.
- 2026-08-20 · THE SEED EDITOR AUTOSAVES; GIT IS THE UNDO: no save/reset/duplicate/delete/raw-JSON ceremony — every edit lands on disk after a short settle (the validator still refuses saves that introduce new reds; a refused value retries only once it changes), and a seed save never reloads the editing client: the dev server suppresses the JSON-module reload and emits an event, the /demo lab defers its reload to the next tab switch so the labs pick up the rebuilt seed exactly when they need it.
- 2026-08-20 · A FULLY FED PET GIVES STATS: every pet item authors a stats block — seed validation reds a pet without one; the editor offers the full stat sheet on any stat-eligible item and authors the total zeroed block on first touch (a first stat starts fixed, min = max, so no transient ever violates the range law).
- 2026-08-20 · ONE FIGHT SYSTEM, THE ONLY SPLIT IS LOCAL VS REMOTE: duels, PvM, dungeons and kolizeum all flow through the same client fight core; a remote fight hydrates from the indexer's projected machine document (contract off the wire + player sources from Character nodes' CHAIN-OWN folded stats + spells from the local seed catalog) and every local input becomes one chain transaction while the mesh relay only smooths the other screens. The runtime is the packet's single numeric normalization door: every presentation and result consumer reads its bigint-native checkpoint, never the raw JSON object handed into it. Never a per-mode fight path.
- 2026-08-20 · CHARACTER SELECTION LIVES IN THE APP-WIDE TAB STRIP: the characters page carries NO roster list — the top CharacterTabs bar (the same one the world uses) is the ONE selector for every character-scoped surface; the page renders only the selected character's detail tabs (equipment/stats/spells/jobs/runeforge). Own-transaction results fold client-side from the proven receipt — the server never re-sends what the player's own transaction caused.
- 2026-08-19 · TRAPS FIRE ON ENTRY ALONE: a trap triggers only when a fighter ENTERS one of its zone cells; since every mover resolves per step, crossing the zone always touches it, and stepping off the edge touches nothing and stays silent. The departure cell never arms a trap — in Move and the local twin alike.
- 2026-08-19 · CHATIMENT USES THE RETRO DAMAGE CAP WITHOUT EROSION: kind 7 is CHATIMENT; actual nonlethal HP lost becomes the authored characteristic up to the summed same-stat stance cap once per active fighter turn, never once per hit or once per stance. Player-sourced damage feeds half its landed value under half the cap; mob-sourced damage feeds in full. Each turn folds into one five-turn gain row, so later turns stack with independent expiry; the normal rank caps are 60/80/100/120/140/200 and critical caps 70/90/110/130/150/220. Ares deliberately omits Retro's erosion rider.
- 2026-08-19 · LIFE STEAL DRINKS HALF: an instant hp steal heals its caster exactly half of the damage that actually landed, floored — never the full hit, never overkill.
- 2026-08-19 · ONE OWNER PER TRANSFORM (engine): an entity's root POSITION belongs solely to placement (place/snap/motion); presentation beats animate only the inner wobble node around identity and capture no rest state. Facing (yaw) is deliberately retained placement state, not a beat capture.
- 2026-08-19 · POOL DELTAS FLOAT FROM EVENTS, ONCE (frontend): floating AP/MP numbers project from `ap_mp_change` (effect reasons only) plus the lasting-row event when no live pool moved — one signed float per fighter per resolution segment; costs, refills, and tackle keep their own presentation.
- 2026-08-19 · THE TRAP ZONE IS THE PAYLOAD'S AREA: one authored fact (the trap's shape/size) decides trigger, display, and effect area — the resolver rewrites payload rows to the zone's geometry and never trusts a second authored area copy; glyphs stay per-occupant. Both twins.
- 2026-08-19 · THE LOG SPEAKS EFFECTS, NOT CONSUMPTION: the combat log shows only what fighters do to each other — contested AP/MP removals speak through `points_contested` (loss, partial dodge, full dodge, steal all visible; a full dodge is emitted truth, never silence); a hit line merges its shield reduction (for example, `lost 45 HP (reduced 5)`), returned spells and lasting stat changes get their own lines; casting/walking costs, refills, and turn switches stay silent.
- 2026-08-19 · ONE CHAT FOR THE WHOLE GAME: a single chat module is the only message history; every stream that speaks to the player (combat log today, world chat later) feeds it as SEMANTIC lines (template key + tokenized values) so the renderer localizes live and paints tokens from one palette; a line is corrected only through the explicit `replaces` door, never by inference. Mounted in the fight HUD until a world HUD exists.
- 2026-08-23 · TEAM RINGS FOLLOW THE PLAYED TURN: every living fighter carries a subtle border-only ring in its team color under its cell; the stronger pulse follows whichever fighter's turn cue is currently being played, including mobs and opponents. Canonical future state never moves or removes a ring before its matching movement or death cue completes; that death then removes the fighter from model sources, so refresh, HMR, and later cue updates cannot resurrect it.
- 2026-08-19 · THE MOB TURN FLOOR IS ONE CONSTANT: the chain already prices every mob turn at TURN_MIN_MS into `turn_started_ms` (and the twin mirrors it); presentation holds the turn card to the same projected `min_ms` on the turn cue — no second clock, no client-side invention.
- 2026-08-19 · COOLDOWN IS LOUD: a spell on cooldown shows its remaining turns as a big centered red number over the card.
- 2026-08-19 · DISPLACEMENT SLIDES: push/pull presentation is a fast slide—no locomotion clip, no reorientation; being shoved is not walking. Teleport/swap stay snaps. A blocked push deals exact Retro 1.27/1.29 collision damage `floor((8 + R·pusher_level/50) × untravelled_cells)`, with `R∈1..8` drawn from the effect's existing deterministic turn-seed stream; Ares has no dedicated push-damage/resistance stats, so those two terms remain zero.
- 2026-08-19 · INDEXING SETS + THE MESH SPLIT: the read layer is N identical self-contained indexing sets (one FalkorDB + its one indexer per pod, per-pod volume). Reader processes boot without waiting for the projection to reach the live edge; their server exposes cached checkpoint lag, while the client owns the explicit unknown-or-over-300 interaction barrier and catch-up presentation. A connection stays bound to one set for life, and a server whose set dies kills itself so orchestration can replace it. Event publishing is split by publisher: chain evt:* rides each set's OWN redis (never a shared bus — N sets would duplicate every event ×N, and cross-set delivery would outrun the reader's own graph), player ephemera + heartbeats ride the ONE cluster mesh redis (one publisher per event — the owning server). No blue/green, no leader election, no dedup: the layout deletes the questions.
- 2026-08-20 · WORK CONVERGES ON ONE EDGE: `edge` is the repository default and only persistent branch; contributors submit PRs to it, while the owner is the sole human ruleset bypass and may push signed commits directly. Contributor PRs require the owner's CODEOWNER approval after the latest push, resolved conversations, and every gate check; feature refs never deploy. Production authority belongs to owner-created semver tags, not another branch.
- 2026-08-20 · DEPLOY CADENCE IS SPLIT BY AUDIENCE: `edge.aresrpg.world` deploys on every green `edge` commit; `aresrpg.world` changes only when a root semver tag stages a release and the owner manually activates that retained build. A normal edge push and a tag preparation move no production domain. Changed backend inputs build under the release semver; unchanged services copy their existing digest to that release tag without rebuilding, so one version still names the complete deployable set.
- 2026-08-19 · SPEED IS PRICED FROM AN ANCHOR, NEVER PER SAMPLE: the stream speed law mirrors the chain's travel_ok — distance from the last PROVEN position over elapsed since it (anchor seeded by the checkpoint's OWN timestamp, re-anchored at most once per second, small named transient slack). A same-world character reread (fight/custody/party projection) preserves that connection's already-validated ephemeral presence and move anchor; resetting it to the older chain position makes the next ordinary walking packet look like a teleport. A world change still resets from chain truth. Instantaneous per-sample speed checks are banned: physics transients legally exceed the budget for one frame. Violation drops use the one protocol-declared reason set and paint the connection card red.
- 2026-08-22 · EVERY POSITION FACT NAMES ITS CHARACTER: `packet/position` carries `character_id`; coordinates never inherit identity from ambient connection state. The server routes it only through that tracked character's proven ownership and checkpoint anchor, so simultaneous characters cannot price coordinates against one another. Client throttling is keyed per character for the same reason.
- 2026-08-19 · ZONE POPULATION IS SERVER-DERIVED, SERVER-SENT: the seed→spawn derivation (zone_math.move) has ONE TypeScript twin, in the server (`zone_spawns.ts` — same prng, same draw order, same ramps; a zone_math.move change lands there the same commit). The client never derives: it receives `packet/zone_spawns` when a discovered zone enters its tracked spiral and again the instant a tracked zone is searched (fresh seed = fresh, unconsumed spawns). Presence and spawn payloads ride the zone-keyed channels — the legacy chunk-tracking pattern, on zones.
- 2026-08-19 · POSITION RESUMES LOCALLY UNDER THE CHAIN'S ANCHOR: the chain checkpoint is the only authoritative resume point; an IndexedDB row keeps the precise local pose, honored ONLY while it explains itself — same character/world, captured under the exact current chain anchor, under 30 minutes old. A character retains one checkpoint DF per visited world, but the graph promotes only the checkpoint matching `CurrentWorldKey` into the active `checkpoint_world/x/z` fields: a same-transaction world sibling makes travel order-free, while a lone checkpoint update is graph-guarded by the current world. A stale remembered world can never force refresh into spectator mode. Chain truth moved = the cache is stale, checkpoint wins. Never localStorage: positions are data, preferences are localStorage.
- 2026-08-19 · THE WORLD HUD READS TWO LANES: per-frame presentation (pose, heading, fps, time-of-day) rides a throttled external feed outside the app reducer; server facts fold through the one world reducer. The north-up minimap owns coordinates, searched-zone veil, delimitation, mob/resource markers and live players; every marker projection takes the selected world explicitly, so retained discoveries from another character/world cannot bleed through. Public/party engage preference lives beside quality/flat controls, never inside a mob nametag.
- 2026-08-19 · CHARACTER SELECTION IS APP-WIDE CHROME TABS: one tab strip at the top of the page area — one tab per owned character, a plus tab that opens character creation — is the ONLY selection door, shown on the character-scoped pages (world, characters, kolizeum). Every character remains server-tracked; selection is a local projection that re-points rendering, camera, gear, stats, spells and jobs through one `character/select` reducer input. No second selector and no selection packet exist.
- 2026-08-19 · RESIST IS PERCENT AND SAYS SO: resistance rows are percentage points cutting final damage; every displayed resist number carries the % unit, derived in one helper — authored copy never hand-writes the unit.
- 2026-08-19 · ROUNDED BLOCK EDGES ARE A NORMAL TRICK, NEVER GEOMETRY: block corners read rounded via the legacy engine's fragment-normal bevel — the mesher flags each greedy quad's convex edges (word B bits 28-31; an edge is convex only when every cell along it borders empty space in the face's plane), and the terrain shader bends the normal within a 0.3-block margin of flagged edges, written as branchless arithmetic (the WebGPU normalNode select-chain trap). Voxel positions, collision, and shadows never change.
- 2026-08-19 · GROUND CLUTTER DERIVES, NEVER AUTHORS: terrain decoration (grasses, ferns, sedges, bushes, flowers, mushrooms, twigs, pebbles, ice spikes) is a pure function of what the column already is — the visible top material's preset picks the kind, its authored colors (hue-shifted, scaled) paint it, and the shader applies the same climate-tint field as the ground. No sprite palettes, no per-biome decoration config, no textures; a new biome gets fitting clutter for free from its materials. Amendment: the sprites are PIXEL ART, because this is a voxel game — plants are crossed pixel-planes (cell-drawn silhouettes, stepped edges, three quantized color bands), minerals are stacked axis-aligned boxes; each sprite is one file under `packages/engine/src/nature/` (shared machinery in `sprite_kit.ts`), and a kind's variant pool mixes several sprite species so neighbours never twin. Density rides a two-octave sharpened field (broad meadow waves + fine patches, true bare gaps — never a linear fade), and dense patches also grow taller.
- 2026-08-17 · PACKAGE LINEAGE IS ORIGINAL + LATEST: deployment pins retain each Move package's immutable original ID and replace only its latest ID after an upgrade; the local compiler derives retry-safe `PACKAGE_VERSION` bumps from the live shared Version, math upgrades before the game, and activation follows as a separate transaction because the new game package ID exists only in the upgrade receipt. Saving that receipt before activation is deliberate recovery state: a rerun compares source `PACKAGE_VERSION` with the live Version and submits only a still-missing activation even when the artifact digest is already current. Republish means release temporary seed custody, atomically clear only the active network's local pins, and restart publication; immutable old chain objects remain, and their FalkorDB projection must be recreated rather than mixed with the replacement lineage.
- 2026-08-17 · GLOBAL GAME STATE IS VERSION TRUTH: the indexer projects the shared Version object and publishes its post-commit freeze transitions on one global channel; each server process subscribes before loading the graph snapshot, then pushes snapshot and deltas to clients. Frontends never read chain state directly; version 0 alone means frozen.
- 2026-08-16 · INDEXING HEALTH RIDES SERVER INFO: the server compares the indexer's post-commit Redis checkpoint marker with the Sui gRPC fullnode head through one cached per-pod reader, then streams the missing count beside cluster online state; the frontend never polls Redis or Sui and only renders that pushed truth
- 2026-08-16 · SUI CORE OWNS GAS RESOLUTION: `tx.gas` is only the programmable GasCoin argument; the SDK never guesses the wallet's first coin or invents default, seed, or deployment budgets. The configured resolver selects payment and the SDK feeds each receipt's exact post-transaction refs forward. The SDK contains no wait or retry policy. Frontend lifecycle owners may rebuild once after a classified no-digest resolver race; kiosk actions first replace the stale cap through their shared runner. An executed transaction never retries.
- 2026-08-17 · DEPLOYMENT PINS APPLY ON APP BOOT: the release ceremony writes `pins.json`, then reloads the app before any player transaction; authenticated SDK sessions stay immutable instead of carrying dev-only hot-rebinding machinery.
- 2026-08-16 · ADMIN SEEDING USES ONE EPOCH SESSION: the connected super-admin wallet authorizes one locally persisted epoch-bound AdminCap plus 50 SUI of refundable working capital (the full 2026-08-17 testnet corpus consumed about 36); its recovery record is bound to the network, admin wallet, and package and remains until the successful release receipt proves the cap deletion and whole gas-coin transfer; status inspection is read-only and cleanup is an explicit recoverable action; the local signer submits sequential protocol-configured seed PTBs, and every seed door including the permanent seal accepts any current AdminCap — the capability type plus epoch validity is the whole authority rule
- 2026-08-16 · SETTINGS ROUTE IS AUDIO + RENDER DISTANCE: Settings holds the global music toggle and the render-distance slider (4–12 chunk radius, null = the quality tier's default, one override door through the chunk manager); quality tier and flat-world controls stay with the world display they affect
- 2026-08-22 · A BIOME OWNS ONE SOUNDTRACK PAIR: the stable `world:biome` identity hash-selects one of the nine shipped roam/battle pairs; walking observes the sampled biome with border hysteresis, and a mounted fight selects that same pair's battle twin. An authored city overrides the sampled biome with its stable `world:city:slug` key across the complete 3x3 footprint, so crossing internal biome borders never changes its one soundtrack pair. A fight reload samples the selected character's chain checkpoint because the live overworld pose is deliberately absent. Music preference gates the one player, while root `music/` remains the single asset home derived into the frontend build.
- 2026-08-22 · OVERWORLD AND FIGHT SHARE THE VITALS BAR: the world bottom HUD renders the same projected HP and equipment-derived AP/MP gems as combat beside ten empty 5×2 action cells; entering a fight replaces those empty cells with the fighter's weapon and spells instead of mounting a second visual language.
- 2026-08-22 · TERRAIN PRESENTS BEFORE DRESSING COMPILES: new world dressing starts hidden and becomes eligible only after one resident terrain frame has rendered. The render loop also starts only after the player's real first focus resolves from the chain checkpoint plus local resume cache; meshing the default origin and cancelling it when IndexedDB returned made far-from-spawn boot slower than the origin-fixed demo. A multi-octave portal shader and dozens of resource materials entering the first WebGPU scene compile blocked the main thread before the chunk scheduler's first tick—mobs and collision worked over an empty ocean for ten seconds. Loading curtains, excess workers, and control gates only hide these ordering bugs.
- 2026-08-22 · TRACKING OWNS MOB TRUTH; DISTANCE OWNS BODIES: the renderer retains every live mob group in every tracked zone, while Three.js bodies exist only when the group's chain point is under 100 blocks from the player. World mount preloads every distinct mob GLB authored for that world, so crossing the body radius clones a parsed source instead of beginning download/decode while the minimap already shows it. Pose samples refresh presentation from retained truth; no population packet or arbitrary budget may hide an approached group.
- 2026-08-22 · ENGINE LABELS SURVIVE BACKEND BOOT: entity, resource, fight-sword and portal label elements are retained beside their render specs and replayed when the async backend attaches. A label call is state, not a best-effort effect—dropping an early mob tag while its model survived made refresh timing decide whether the card existed. Resource cards expose an invisible nullable world anchor to the one per-frame label registry instead of inserting an uncounted CSS2D object that makes the renderer skip camera frames and visibly drift before snapping back.
- 2026-08-22 · ENGAGE PREDICTS ITS PRESENTATION, NEVER ITS RESULT: pressing E re-resolves the nearest eligible group from the live pose at that exact input, then immediately hides that one tracked mob group and calls the engine's one fight-sword ceremony at its chain point: legacy grow, spinning fall and wobble, then one earth burst + impact sound and the placement-window sink. A React-rendered prompt may never donate its earlier path position to the action. The transaction fires from the newly-added pending row, never the raw key message, so repeated E input produces one state delta and exactly one wallet call. The planted pose retains a slight legacy lean instead of being zeroed straight, its terminal depth derives from the rotated GLB bounds, and its label keeps a constant world-space lift instead of inheriting the 2.5× root scale. The pending sword is replaced by the canonical fight sword, which stays for the fight's whole non-ended lifetime; the engine suppresses swords whenever a board is mounted. The reversible pending row survives transaction certification until a canonical fight, consumed-zone row, or mounted seat replaces it. A rejected transaction deletes the row and restores the mob; a validator stale-object conflict from another player taking the pack becomes clean race copy instead of encoded Sui internals. The client never predicts a fight id, board, seat, or consumption bitmap.
- 2026-08-16 · RELEASE DEPLOYMENT HAS THREE HONEST BOUNDARIES: the Node-only compiler under `scripts/` emits unsigned five-package artifacts; the runtime SDK owns no filesystem or subprocess code. Release tooling records only receipt-derived `pins.json`; the explicitly connected master wallet signs named authorization actions while an epoch-bound local AdminCap performs ordinary release writes.
