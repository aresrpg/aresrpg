# DECISIONS — the owner's mental model

This file makes any agent think like the owner. Patterns first — they decide the calls he is
not in the room for. Rulings second — settled choices, never re-derived, never undone silently.
One line each. A new entry lands the moment a choice carries a motive worth reusing.

## Patterns — how to think here

- 2026-08-23 · SUI DISPLAY ART IS A STABLE BUILD DERIVATION (owner missing explorer art): wallets and explorers read unfingerprinted `aresrpg.world/item/<item_type>_hd.png` and `aresrpg.world/classe/<classe>_<sex>.jpg`; Vite derives those exact routes from `seed/icons`, while the app reads the same item route instead of emitting a second hashed HD corpus. Character portraits are deterministic renders of the composed GLBs; only the four authored class models × two sexes are stored, and the existing class-model fallback fans them out to all 24 public URLs. A duplicate `public/` asset home is forbidden.
- 2026-08-23 · TERRAIN PREWARMS ONE RESOLVED INITIAL FOCUS (owner off-origin reload + demo regression): the player resolves its selected character's saved/checkpoint position before constructing the world, then passes that focus through renderer and backend so the far shell overlaps WebGPU boot at the correct location; the demo passes its known origin. Eager implicit-origin work delays off-origin players, while deferring all work until first render throws away useful backend-boot overlap and regresses time-to-pixel.
- 2026-08-23 · A PACK TAG RIDES THE PACK, NOT A MEMBER (owner visual correction): one group card anchors at the live horizontal centroid of every roaming member and above the tallest current seat. Attaching it to member zero makes the label drift to one edge and lie about the group as independent wander spreads it.
- 2026-08-23 · REACT PRESENTATION PROPS ARE JSON-SAFE PROJECTIONS (owner spell-cast crash): BigInt-rich contract checkpoints stay inside their state/projection owner; a changing child prop carries only the numbers, strings, and booleans it renders. React 19's development performance logger deep-diffs props and JSON-stringifies primitive arrays, so passing a checkpoint crashes on its BigInt queue even though React can otherwise render BigInt scalars. Immutable contract objects such as the fight board are pinned by semantic identity instead of reacquiring a cloned reference every command.
- 2026-08-22 · THE GROUP-SIZE RAMP MUST SATISFY ITS NAMED LANDMARK (owner singleton incident): at 2,000 blocks, deterministic bounds are 2..4 so the uniform average is exactly three; the first outer zone already permits multi-mob packs. A linear integer ramp whose upper bound stays one through the first ~1,200 blocks makes every nearby group deterministically singleton despite a constant named `AVG3_AT`.
- 2026-08-22 · A SUCCESSFUL RESULT STEP LATCHES UNTIL PROJECTION ADVANCES (owner abort 1713): settlement and each item-type claim are automatic once, then their semantic key stays latched while the indexer removes that work row. Inventory or unrelated state updates must not resubmit against the stale resolution snapshot; `claim_drop` consumes every matching item-type row, so a duplicate correctly aborts “no such drop.”
- 2026-08-22 · REMOTE VICTORY IS CANONICAL, A LETHAL DRAFT AUTO-COMMITS (owner false-result incident): a local turn draft may animate a mob at zero HP, but it cannot close a remote board or create a result receipt. It enters the End Turn queue automatically; only an ended streamed checkpoint declares victory and starts settlement. Otherwise Victory traps the player outside an active chain fight and refresh correctly—but absurdly—puts them back.
- 2026-08-22 · A LETHAL ACTION IS ITS PTB'S TERMINAL BOUNDARY (owner abort 1706): a drafted turn normally appends `end_turn`, but an action that locally seals the fight submits the ordered actions without it. The lethal cast/strike already writes `Fight.ended` and emits `FightEnded`; appending `end_turn` then calls the active-phase guard on an ended fight and rolls the entire kill back.
- 2026-08-22 · RECEIPT-FRESH OWNED REFS WAIT FOR THE READ NODE (owner loot-claim incident): before a terminal kiosk action composes, the SDK polls until its load-balanced node can see at least the PersonalKioskCap version already held in the receipt-fed cache. Re-reading once is not a refresh when that node answers with the previous version; composing the newer ref against it fails before submission with “provided version doesn't match.”
- 2026-08-22 · END TURN WAITS FROM LOCAL OBSERVATION, NOT CLOCK AGREEMENT (owner abort 1724): the client queues for the chain's minimum duration plus a small submission guard measured from when that turn identity was locally observed. Comparing browser wall time directly with Sui Clock assumes synchronized clocks and can submit early. A dry-run 1724 is zero-gas and restores the buffered draft into the queue; an executed failure has a digest and is never retried.
- 2026-08-22 · PRESENTATION RELEASE IS A RENDER-TIME DERIVATION (owner PvM snap incident): while a cue batch exists, entities render from its retained checkpoint; the render that observes an empty queue selects canonical state immediately. A React effect that copies canonical state one frame later visibly produces end → start → end even though both simulation and chain checkpoints are correct.
- 2026-08-22 · A FIGHTING CHARACTER LEAVES PRESENCE, NOT THE WORLD WINDOW (owner multiplayer incident): every roster character keeps its independent zone subscriptions while fight-custodied, but only free characters publish bodies or answer presence probes. The fight row renders one sword for its whole non-ended lifetime; nearby accounts see body XOR sword, never both and never neither.
- 2026-08-22 · CASUAL FIGHT SECRETS ARE TEAM-SCOPED (owner): an invisible fighter is omitted entirely for every other team and spectators while allies see the shimmer; traps render only to their owner's team, while glyphs remain public. Wallet ownership never grants tactical vision across opposing teams.
- 2026-08-22 · RANGE REMOVAL REACHES MODIFIABLE BASE RANGE (owner rules correction): for a modifiable spell, additions and removals apply to `authored_max + gear_bonus` as one saturating value in both Move and the fight twin. Folding removal into an unsigned bonus first makes zero-bonus spells immune and is forbidden.
- 2026-08-22 · A RESULT WAITS ONLY FOR ITS VIEWER'S DURABLE WORK (owner settlement incident): another participant's settlement never disables Continue. An empty `packet/fight_resolutions` after an ended result proves the viewer's settlement and claims are complete even when no intermediate settled row arrived; the visual receipt keeps its declared loot while the work row may disappear.
- 2026-08-22 · TURN WITNESSES ARE IDEMPOTENT PRESENTATION INPUTS (owner PvM rollback incident): the same `(fighter, seed)` may arrive from the transaction receipt and indexer stream; it enters the fight runtime once. Duplicate delivery never invents a crank or replays start/end cells.
- 2026-08-22 · CHAT VOICE IS THE SELECTED CHARACTER (owner): every send reads the current tab's character ID at the input edge; the server derives its name from that tracked character and never accepts a client-supplied username. The local echo reads the same selected roster row directly, so switching tabs changes both wire identity and displayed speaker together.
- 2026-08-22 · FIGHT PITS ARE GEOMETRY, NOT SCREEN INK (owner visual incident): board holes cut the slab with depth-tested walls and a bottom kept inside the board's one-block ground clearance. Disabling depth to defeat terrain draws every cavity over fighters and floor tiles as giant black prisms; a cavity that needs overlay ordering is modeled at the wrong depth.
- 2026-08-22 · FIGHT EVENTS ANIMATE; THE FIGHT OUTPUT RECONCILES (owner incident): every projected Fight write publishes one trailing `FightProjected` after its ordered event witnesses; the server preserves witness order and sends only its newest requested checkpoint, while the client queues every presentation batch until played. A single replaceable batch dropped damage floats and turn sounds even though the combat log saw them, and an older async checkpoint read resolving last rolled mob cells, HP, AP and MP back until refresh.
- 2026-08-22 · THE MARKETPLACE IS AN OBSERVED WINDOW, NOT A CLIENT DATABASE (owner, deprecated design restored): BUY keeps the archived seven-group browser, SELL keeps own listings + price card + inventory, and HISTORY keeps the 30-day ledger + explicit kiosk-proceeds collection; gift/send stays deleted because p2p exchange owns that job. Opening a browse group sends its exact chain-category set, the server pushes one graph slice plus retained sales and streams deltas, and one client reducer folds packets and SDK receipts. Native Kiosk PTBs remain the sale mechanism; generic stack split/merge doors mutate amounts while preserving locked custody, and listing remains a separate SDK-composed Kiosk command.
- 2026-08-22 · ONE STACK PER ITEM TYPE AND KIOSK (owner): the client always targets the largest unlocked same-type stack for a new yield and coalesces existing fragments before splitting the exact amount an action needs; listed stacks are never mutation targets, an unsold lot merges back on delist, and bought or exchanged lots merge after their transfer policy confirms in the same PTB. Move owns only custody-safe `split_stack`/`merge_stacks` amount writes plus the existing mint deposit; actions stay strict and refuse a client that submits the wrong object shape. Random-terminal doors cannot prepend maintenance, so they target the canonical unlocked stack without inventing another stack-management branch.
- 2026-08-23 · THE FIGHT RESULT IS A MONOTONIC RECEIPT, LEVEL-UP CELEBRATES FIRST (owner correction): the live fight owns every terminal cue; only after its presentation queue drains may the result card appear or settlement begin. `DropsRolled` declares every participant's loot to every watcher, including spectators, and the card aggregates by item type under stable semantic keys. Settlement and claims execute automatically with no happy-path buttons; every terminal kiosk action refreshes its owned PersonalKioskCap ref before composition, while inventory projections never feed the card. An ended Fight projects durable `RESULT_FOR` work until the seat settles and every drop is gone; reconnects reconcile that row and executed failures latch for explicit retry. A level gain mounts the radiant celebration above the still-open result and must be acknowledged first; enemy mobs never render character-progression chrome.
- 2026-08-22 · A TURN IS ONE TRANSACTION (owner, deprecated contract restored after regression): movement, casts and weapon strikes are deterministic local drafts relayed immediately through the server mesh for peer presentation; none opens a wallet or mutates chain truth alone. End Turn commits the ordered draft as one PTB (`move_fighter` / `cast_spell` / `weapon_strike`, then terminal `end_turn`), so one turn has one gas payment and one rollback boundary. Its first press latches the button while the player's card stays highlighted through confirmation; refusal unlocks the same turn, while confirmation folds the receipt's exact `TurnSeedUsed` mob witnesses into immediate deterministic presentation and a changed streamed checkpoint releases the latch. Reset, refresh, canonical turn change or refusal discards the draft; a canonical checkpoint alone reconstructs the full playable AP/MP range. Placement, ready/start, crank and forfeit remain separate lifecycle transactions. The chain accounts three virtual seconds per atomic mob turn in the next player's start time, while the presentation queue holds each mob card for three real seconds from its cue start before the following card may highlight; the 45-second force-pass clock is shown only when at least two human fighters exist.
- 2026-08-22 · WATCHING A FIGHT GRANTS NO FIGHTER VOICE (owner): the server's fight watch is delivery only; a spectator carries no seat and can never publish an action. Placement/forfeit relays must name the connection's projected seat, and active relays must additionally name the projected current fighter. This is authorization, not action simulation: happy-path clients remain trusted for legality until the server fight twin is deliberately built.
- 2026-08-22 · ALL CHARACTERS STAY TRACKED; SELECTION ONLY PROJECTS (owner): the server reconciles the capped roster itself and maintains an independent position anchor, zone spiral, party, and fight for every character; the frontend never asks to mount or unmount one. Redis demand is the union of those windows, so overlaps share one subscription and one cached zone fact; `packet/tracked_zones.character_id` names each window. The frontend retains the same union and projects only the selected character's window/fight into rendering. Tab selection performs no network operation. The last global Redis release still waits ten seconds so packet cadence never becomes subscribe/unsubscribe cadence.
- 2026-08-22 · SIX CHARACTERS PER APP ROSTER (owner): `MAX_TRACKED_CHARACTERS = 6` is shared protocol law. The server deterministically sorts by character ID and exposes only six before the client learns the roster; that capped ID set is also the tracking allowlist, so a modified client cannot reveal a seventh. The app hides every creation door and refuses creation once six rows are visible. Legacy on-chain excess remains untouched and invisible.
- 2026-08-22 · A ZONE SEED IS SPAWN GENERATION IDENTITY (owner): when a zone re-rolls, its old mob/resource population disappears before the replacement arrives, and every rendered group/pack id includes the new seed. Already-created fights are independent chain objects and survive the population flush.
- 2026-08-22 · A RESOURCE PATCH IS ONE CHAIN PACK WITH VISUAL SEATS (owner-confirmed): the seed draws one pack point and node count; the client deterministically seats that many adjacent blocks, and every block gathers the same pack index. Job, tier, protector, and rare identity stay on the authored resource row, never copied onto the spawn wire. Gathering affordances report the level gate first, then the matching tool; a fired protector verdict is projected on the character and requires an explicit player action to create its solo fight.
- 2026-08-22 · A SIDE'S RULE DECIDES WHO MAY TAKE IT, NEVER ITS POPULATION (owner): every fight side carries an access rule (`PUBLIC` · `GROUP` · `INVITED` · `UNSET`) and its opener's identity, and that rule is the only authority on who may sit there — claiming an UNCLAIMED, EMPTY side is the one case a joiner writes the rule. Reading the crowd instead (`players == 0`) let a bystander take a duel's reserved seat and let a side whose last player forfeited be re-opened under a stranger's setting. PvM, duels, party fights and kolizeum differ only in which rule each side is INSTANTIATED with — a new fight flavour never earns a new field.
- 2026-08-22 · THE WIRE SPEAKS CHAIN COORDINATES (owner incident): presence rows, fight rows and position packets all carry chain-space cells; the client shifts to its own space ONLY at the render edge. Converting one side of a comparison is invisible in a unit test with a hand-built fixture and fatal in the world — a duel matched −14 against 49986 and every duel died on its timeout for hours.
- 2026-08-22 · A SEAT IS THE MOUNT (owner incident, amended): what makes a fight board eligible on the WORLD PAGE is the SELECTED CHARACTER holding a seat in it, derived from the chain checkpoint — never a UI gesture or another character owned by the same wallet. Fight state stays hydrated while browsing, but its canvas, camera, HUD, and battle music never render outside the world page. Selecting outside releases the board; selecting another seat in the same fight keeps that board and switches its HUD. A spectator holds no seat and is the one case that mounts explicitly.
- 2026-08-22 · A HAND-WRITTEN MIRROR IS PINNED TO THE COMPILED BYTECODE (owner incident): every decoder that mirrors a Move struct or event is checked field-by-field, names AND widths, against the built package — never against a committed snapshot of itself, and never by a human reading a diff. BCS is positional: one missing field made the indexer decode the next field's bytes, retry the checkpoint forever, and freeze every client on a stale world for ten hours. A green suite that includes a generated-contract check is worth nothing if a red one still reaches `edge`.

- 2026-08-21 · PRESENCE FACTS RIDE THE POSITION STREAM (owner): a per-player world fact another client must see (mounted, and anything of that shape) travels as a FLAG on the existing position packet — never its own packet and never a periodic sync timer. A discrete toggle forces one packet immediately, so it lands within a tick, inherits the stream's throttle for free, and the server clamps any claim the chain contradicts (riding without an equipped pet). Distance throttles may drop positions, never a state toggle: a player who toggles then stands still sends nothing more to carry it.
- 2026-08-21 · PROJECTION IS THE STREAM TRIGGER (owner): when the indexer projects a state write the player could not decode from their own receipt (a mint's rolled contents, a craft yield, a gather stack, a trade claim), the projection itself publishes and the server streams the row — the client NEVER sends a request packet to backfill state, and a receipt's only jobs are folding what it literally contains and unlocking the next action. One mechanism per fact class: the object output is the trigger (no Move event required), so every future mint path streams by construction instead of growing its own refresh.
- 2026-08-18 · PET MODEL IDENTITY IS ITEM IDENTITY (owner): every category-pet item owns exactly one `seed/models/pets/<item_type>.glb`; world companions and mounts resolve that filename directly, with no catalog, prefix stripping, inferred family, or placeholder. `pet_movement` is the one authored walk/swim/fly fact; absent means walk. A ridden pet replaces its follower, seats the character from its rendered height with `SIT`, applies the controller's exact 1.5× speed scale, and a fly pet permits held-jump gliding.
- 2026-08-18 · POOL EFFECTS PRICE THE TARGET'S USABLE TURN (owner): AP/MP remove and steal contest the live pool only when the target is active, otherwise the next base pool folded with existing rows; a zero-turn row applies once—immediately for an active target or at the next refill for an inactive target—and never both.
- 2026-08-18 · EFFECT DURATION BELONGS ONLY TO TIMED KINDS (owner): damage formulas, displacement, teleport, swap, trap placement, and dispel require `turns = 0`; glyph, shield, reflect, invisibility, return, and redirect require a positive duration. Move construction and seed validation reject the wrong class.
- 2026-08-18 · CASTER-ONLY EFFECTS IGNORE TARGET GEOMETRY (owner-confirmed by Bleeding Word): target filter `only_caster` resolves exactly once on the living caster, independent of the aimed cell and authored area; it is a recipient identity, not a zone predicate. Move and the local fight twin share this rule.
- 2026-08-18 · PERCENT-LIFE DAMAGE ROLLS ITS AUTHORED BAND (owner-confirmed by Rousing Word): resolve one deterministic value between `value` and `value_max`, multiply the target's maximum HP by that percentage, then apply the row's elemental resistance. A displayed percentage range may never collapse silently to its minimum.
- 2026-08-18 · THE COMBAT LOG REPLAYS FIGHT EVENTS (owner): every fight surface renders one client-only transcript from the canonical ordered fight events; VFX acknowledgement clears only the active presentation batch, local turn reset truncates the abandoned branch, and no log line enters chat, wire, or combat truth.
- 2026-08-18 · ELEMENTAL SHIELDS SCALE AT APPLICATION (owner): a reduce-damage row freezes `base × (100 + caster's matching elemental characteristic) / 100` when applied; raw damage and recipient resistance never enter shield creation. A named-element shield mitigates only matching incoming damage, while an empty element is universal. Move and the local fight twin share the formula and matching rule.
- 2026-08-18 · CINEMATIC ATMOSPHERE IS MOOD PLUS LOCAL LIGHT (owner): persistent depth comes from the existing Hillaire aerial perspective plus a closed-form humidity-sensitive height integral capped at 22%; god rays are a separate high-only, depth-occluded radial sun effect with 24 energy-normalized jittered samples at 40% linear resolution. Shafts stay visible for a moderately offscreen sun through a smooth peripheral fade, but disappear behind the camera, at night, or underwater. The archived dapp's omnipresent half-resolution 75-step noisy fog march and 100-sample ray pass are reference mood only and may never return as runtime architecture. Bloom and display grade may amplify the resulting light, but low quality and fight presentation remain direct.
- 2026-08-18 · FIGHT CASTS HAVE THREE AUTHORED VFX BEATS (owner): every spell renders caster charge, falling delivery, then target impact on one serialized clock; element owns palette and base silhouette while resolved spell mechanics select the pack variant. A generic sphere is only an unknown-content fallback, never the normal path.
- 2026-08-18 · FIGHT MOVEMENT PLAYS THROUGH TRAPS (owner, amended 2026-08-18): accepted steps remain in event order; any movement touching a trap area—including the first movement made while already covered—consumes only that trap, pauses for its trigger, sound, hit, and floating number, then resumes the remaining path with the original whole-path gait. When traps overlap, damage traps resolve before displacement traps; inside one payload, damage rows resolve before push/pull/teleport rows. Presentation never jumps directly to the final checkpoint.
- 2026-08-18 · INVISIBILITY HIDES POSITION, NOT MOB TURNS (owner, legacy parity): a mob with no visible enemy searches toward its own starting-band anchor, consuming no hidden fighter position; invisibility creates repositioning pressure rather than a free skipped turn.
- 2026-08-18 · FIGHT ACTION FACING IS CARDINAL (owner, amended 2026-08-18): placement faces the opposing band only as the initial default; a completed move retains its final travel direction, and a cast faces its targeted cell before the attack beat. Action-derived facing is quantized to four directions and survives canonical entity refreshes through the shared engine door.
- 2026-08-18 · MATERIAL PRESETS OWN SURFACE STRUCTURE (owner, amended 2026-08-18): a world material authors only color plus one semantic preset; the engine preset owns recognizable seamless procedural albedo topology and signed micro-roughness packed into the same mipmapped RGBA array. One world-space texture field spans several blocks; block identity, greedy-quad identity, dark frames, and per-block layer switches never create texture seams. The active quality tier owns one 16/32/32-pixel texture array for low/medium/high and replaces that resource on a tier change; high spends on lighting, not a larger procedural bake. Seed-side granularity, shine, pattern knobs, texture assets, and extra terrain samples are forbidden.
- 2026-08-17 · PUBLIC DEMO IS THE COMPOSITION CONTRACT (owner): `/demo` ships without login and owns only its HUD; it composes the same seed projections, game core, engine, fight simulator, settings, models, and presentation doors as the app. A missing demo control exposes a missing production API — demo-only renderers, copied fixtures, private engine shortcuts, and network observers are forbidden.
- 2026-08-17 · THE FIGHT SIMULATOR LIVES IN `/demo` (owner): the public composition lab owns the complete local fight authoring surface; the authenticated player app has no simulator route, navigation item, or persistence observer. Simulator state and presentation stay shared because `/demo` exercises the same fight runtime as production.
- 2026-08-17 · CRAFT PROFESSION COMES FROM THE OUTPUT (owner): recipes for gear and keys never author a job; immutable and the seed composer mirror Move's category-derived profession, while categories shared by several professions retain the one authored fallback job. The admin edits a recipe beside its output item and exposes a profession selector only for that fallback.
- 2026-08-17 · ADMIN ITEM AUTHORING IS ITEM-CENTRIC (owner): the content editor hides stable string IDs, groups items by immutable category, orders them by level then name, and joins the separately-authored `recipes.json` row by output identity. Defined stats stay above the power curve; available stats stay below it.
- 2026-08-16 · FIGHT PRESENTATION IS ONE ORDERED CUE EDGE (owner-approved): canonical local, streamed, and reconciled fight events project once into immutable cues; the game owns their serial queue, the engine owns model beats and one bounded typed VFX primitive, and the frontend owns audio. Persistent effects derive from the checkpoint, never presentation state, and local mode changes only the fight input source.
- 2026-08-15 · ENTITIES HAVE ONE ENGINE DOOR (owner): terrain and fight boards submit the same plain entity spec with a world or fight-cell anchor; the engine alone loads and animates mob or character models, and a character appearance owns its body, optional Head-bone hair, three colors, and Head/cape worn cosmetics
- 2026-08-16 · FIGHTERS FACE THE OPPOSING BAND (legacy parity): placement orientation is layout-independent — every fighter declares its side through the shared entity door, and the engine faces it toward the opposing starting band centroid with `atan2(Δx, Δy)`; simulator-specific yaw constants are forbidden
- 2026-08-15 · FIGHT-BOARD BLOBS HAVE ONE ENGINE DOOR (owner): placement cells, ranges, spell AoE hovers, glyphs, simulator probes, duels, and Kolizeum all create colored `single` or inset `per_cell` areas through the shared fight-board API; spell AoE hovers are always one red `single` shape, per-cell reveals travel outward from an origin and reconcile updates by cell identity, and any single area grows as one cartoon shape; overlapping meanings use explicit blob priority and remove covered cells from lower translucent layers; the engine batches each per-cell area into one instanced draw while retaining per-cell reveal identity — callers supply cells and meaning, never another renderer
- 2026-08-17 · FIGHT STATUS VISUALS CROSS ONE PLAIN-DATA DOOR (owner, visibility amended 2026-08-22): fight state decides which entity carries a status visual, while the engine owns its pixels; allied invisibility supplies `{ kind: 'invisibility' }` and reuses the retained skinned heat-haze treatment without remounting the model. Enemy and spectator projections omit the entity as casual tactical presentation; chain state remains public.
- 2026-08-17 · INVISIBILITY BREAKS ON IMMEDIATE DAMAGE (owner): only a cast that resolves direct damage consumes the caster's invisibility; placing a trap or glyph stores its damage for a later zone resolution and never reveals the caster at placement time. Move and the local fight twin share this predicate.
- 2026-08-16 · FIGHT PREVIEWS COME FROM FIGHT TRUTH (owner, amended 2026-08-18): the fight package derives steered movement paths and exact spell targetability from the same rules the command resolver executes; the game submits that path unchanged and maps projections to the shared blob API, while the engine animates accepted `fighter_moved` events through the one entity door. A hovered fighter temporarily owns the displayed MP range; the active fighter path appears only when no fighter hover overrides that range.
- 2026-08-16 · CRITICAL DRAWS ARE PER TURN AND SPELL (owner): Move and the fight mirror derive one stable critical roll from the public turn seed plus canonical spell name; target and cast slot never enter that key, so aiming or repeating a spell cannot reroll it, while different spells can differ during the same turn
- 2026-08-16 · SPELLS MAY TARGET EMPTY CELLS (owner, confirmed): range, launch-line, line-of-sight, AP, cooldown, and cast caps decide whether an anchor is castable; a living occupant is never required. Empty-or-occupied REQUIREMENTS live on the effect kinds that own them, never on a spell flag: a trap anchor aborts on a living occupant, teleport no-ops onto a body, swap needs one — so the authored `free_cell` field is retained wire data with no rule behind it. AoE previews run the real fight resolver on a disposable checkpoint, so affected-fighter nametags never duplicate shape, target-filter, roll, or damage rules in the UI.
- 2026-08-16 · FIGHT GAIT USES THE WHOLE ACCEPTED PATH (legacy parity, owner): one or two cells use the WALK clip at 480 ms per cell; three or more use RUN at 170 ms per cell — derive gait once before playback so segmentation never reclassifies a run
- 2026-08-16 · SIMULATOR TURN RESET IS A LOCAL CHECKPOINT (owner): reset restores the exact checkpoint, render identities, and deterministic seed cursor captured at the current player-turn boundary inside `@aresrpg/fight`; it is unavailable in remote mode and never enters the wire
- 2026-08-15 · SIMULATOR ROSTERS SURVIVE RELOADS (owner): locally authored simulator characters live in the existing `aresrpg_simulator` IndexedDB roster store and hydrate through the simulator reducer; board placement and fight state remain ephemeral
- Derive, don't register: identity comes from deterministic derivation over natural keys (a character's address = owner + name under the gate) — findable without an indexer, unique by construction; a registry table is a smell
- Public data files are pure data: a served JSON carries only fields a consumer reads — no prose, no ruling dates, no authorship trails, no internal references; provenance lives in git history, which already does that job
- One content home, HARD LAW (owner 2026-08-12): `seed/` holds the game's content truth — one file per domain, no version-stamped twins, no pointer files, no frontend-side JSON copies; the frontend consumes seed/ through the build (a generated artifact is derivation, a committed copy is a violation)
- 2026-08-14 · SEED PHYSICAL LAYOUT (owner): `seed/` has exactly four authored homes: `content/` for domain JSON, `icons/` for images, `models/` for geometry, and `sounds/` for audio. There is no `assets/` wrapper and no `sprites/` folder; semantic subdirectories exist only to prevent collisions or group real model families.
- 2026-08-14 · MOB ICON IDENTITY (owner): `seed/icons/mobs/` contains the canonical mob icons only. Model-source `hy_*` renders are duplicate previews, not another asset family, and do not belong in the repository.
- 2026-08-14 · MODEL ASSET HOME (owner): every authored 3D model lives under `seed/models/`. Model families use semantic subdirectories (`mobs/`, `characters/`, `cosmetics/`, `pets/`), standalone props live at the models root, and `cosmetics/` carries the complete canonical worn-model corpus rather than a frontend copy.
- 2026-08-14 · SOUND-EFFECT ASSET HOME (owner): sound files use the unabbreviated, flat `seed/sounds/` directory. There is no `sfx/` alias and no redundant `fight/` subdirectory; runtime fallback URLs may keep their public `/sound_effect/` contract as a build derivation.
- 2026-08-18 · FOOTSTEPS FOLLOW MATERIAL PRESETS (owner, amended 2026-08-18): world roaming accumulates grounded horizontal distance and renders a subtly varied footstep from the sampled terrain, structure, or liquid `MaterialPreset`; the preset list is the coverage contract. One speed-driven heel/toe-plus-friction exciter feeds the material response: modal resonances for solids, stochastic particles only for aggregates, and descending bubbles for liquid. When synthesis lacks ecological validity, a small proven or CC0 recorded impact set may replace that preset's exciter from the flat `seed/sounds/` corpus, decoded once and provenance-recorded; cadence and material selection remain shared. Footsteps add no parallel block-name taxonomy, timer cadence, fight-board duplication, or per-frame audio graph.
- Take facts from the context, never as parameters: the sender lives in `ctx` — a parameter that repeats what the context knows is a redundancy that can lie
- Flatten until forced: no wrapper struct for three colours, no subfolder for one package, no explicit dependency the toolchain injects itself — hierarchy must earn its existence
- Denormalize for the reader, with exactly ONE writer: `level` sits on the character so wallets can read it; only the progression door writes it, in the same transaction as the xp it derives from
- The module boundary is the security boundary: data modules own shape and invariants behind public(package) doors; gate modules own policy (names, prices, whitelists); consumers compose doors
- Gas outranks storage purity: players pay computation forever, while storage deposits refund on deletion — snapshot sealed data into short-lived objects freely, never recompute per action what a stored copy answers; derivation is for LIVE state that can drift
- Latest of everything, no duplicates: lean on toolchain defaults over manual pins; a pin is a scar, not a habit
- The pattern library is the aresrpg-legacy repository (the original testnet game — lean, proven; the frozen move-old/rpc-old trees live in git history) · before designing any mechanism, check how legacy solved it and carry the pattern, not the code
- PTB-safe stays OUT of the modules: anything a frontend PTB can do safely never pollutes Move — a Move signature must ask only for what it genuinely needs. ## Rulings

- 2026-08-22 · THE CHALLENGE IS THE INVITATION — REVERSES the 2026-08-20 off-chain duel handshake (owner): `challenge_duel` names the target and RESERVES side B for that character (`ACCESS_INVITED`), so the fight object itself carries the invitation and the challenged client READS it off the fight row already streaming to everyone nearby. This deletes the invite/accept/decline relay, its TTL timers, and the position matching that guessed which fight belonged to whom — all of which existed only because the chain door had no target concept. The price, accepted deliberately: a challenge costs gas before consent, and a refused duel leaves the challenger on his own board to leave (his board opens by itself, so nothing is ever stuck invisibly).

- 2026-08-22 · THE GATE IS DRESSING, THE CHAIN IS THE BOUNCER (owner): every world's portal renders unconditionally at client 0;0 as engine dressing (one TSL disc, sunk into the terrain, exits with the flatten's water phase) — no per-world config exists to drift; the approach prompt is PROXIMITY-gated like the mount chip, never cursor-hover (looking away must not unarm travel); locked worlds grey out in the picker while the chain re-asserts every entry level (greying is manners, never a guard); the arrival folds only from the receipt's own `WorldJoined` event, and the refreshed roster anchor makes the server remount and push the new surroundings.
- 2026-08-21 · AN ID LEARNED FROM A PEER IS WAITED FOR, NEVER ASSUMED READABLE (owner incident, the duel join): `fullnode.testnet.sui.io` is a load balancer over many nodes, so the node WE read is not the node the peer wrote to — an object id that arrives over the relay the instant its transaction commits can be invisible to us for a checkpoint. Two hydrate doors, and the caller picks by meaning: `hydrate_unknown` where absence is a legitimate answer (does the seal exist yet?), `hydrate_required` where the object provably exists and only our node is behind (a duel's fight id) — the latter waits a bounded ~3s and then throws NAMING the id. A hydrate that finds nothing never returns quietly: the old silence surfaced later as "hydrate it first" about an object that had just been hydrated, which sent the debugging in the wrong direction entirely.
- 2026-08-21 · ONE DRY RUN, ONE FIXED GAS BUDGET, GAS COINS ARE THE RESOLVER'S (owner, budget amended 2026-08-22): a transaction is a dry run then an execution — the dry run happens ONCE, on the unsigned bytes, before the wallet opens, and `GAS_BUDGET_MIST` is pinned at 0.2 SUI so no estimation dry run is needed. The SDK NEVER names the gas coin: which coin — or whether a coin exists at all, since an address may hold its SUI as an address balance instead of `Coin` objects — is the Sui resolver's answer, and pinning one receipt-fresh ref with no fallback is what told a wallet holding 1000 SUI it was out of gas. A dry run refused for gas is OUR budget, not the player's wallet: it raises its own toast and must never read like an empty balance.
- 2026-08-21 · ADMIN OVERVIEW READS ARE WALLET-FREE, THE TREASURY IS A NAME (owner): every chain-readable fact on the admin page (treasury balance, policy royalty balances) loads immediately through the SDK's read-only client — the ONE sanctioned direct Sui GraphQL path (sdk/admin) — and a wallet connection exists only to SIGN (claim, publish). The treasury address is NEVER hardcoded off-chain: it resolves from SuiNS (`treasury@aresrpg`) lazily, only when the admin page loads. Off-chain metrics (MAU/DAU) wait for their server route, never a chain workaround.
- 2026-08-20 · ONE SEAT PER ACCOUNT, THE EVICTED WINDOW STAYS DOWN (owner): the server keeps one socket per address (same-pod `REPLACED`, cross-pod `ALREADY_CONNECTED`); the kicked client parks the link in a terminal red state with a "connected from another place" modal and NEVER auto-reconnects — a retry would only steal the seat back and ping-pong both windows. Reconnecting is an explicit human action.
- 2026-08-20 · THE SDK IS WRITE-ONLY, THE WIRE IS SNAPSHOT-THEN-DELTA (owner): the SDK never reads chain state beyond transaction-building facts (object refs/versions, balances) — everything a player sees comes from indexing through server packets; the inventory loads ONCE at boot and then moves only by per-item add/update packets (packet/item_updated, the bounded packet/items_request for receipt-named ids) — never a bulk re-push. Pending claims settle SILENTLY (modules/claims.ts) with zero claim UI; an empty gas tank raises the one blocking top-up modal.
- 2026-08-20 · CONTENT EDITION LIVES ON /DEMO, THE ADMIN TAB IS CHAIN-ONLY (owner): the seed content and biome editors (dev-server-only surfaces) belong to the /demo composition lab, where the live engine renders the edited recipe (spline edits rebuild real voxels, debounced); the in-game admin tab keeps only what needs the authenticated link or a signing wallet — stats, module publish, fee collection. A wallet connection exists to SIGN chain transactions, never as an access gate.

The departure cell never arms a trap — in Move and the local twin alike.

Mounted in the fight HUD until a world HUD exists.

- 2026-08-19 · INDEXING SETS + THE MESH SPLIT (owner): the read layer is N identical self-contained indexing sets (one FalkorDB + its one indexer per pod, per-pod volume); a set is READY only when caught up to the live edge (readiness probe on its own checkpoint marker's chain timestamp — no coordination), and servers round-robin at CONNECT time across ready sets, bound for life — a server whose set dies kills itself and k8s respawns it onto a live set. Event publishing is split by publisher: chain evt:* rides each set's OWN redis (never a shared bus — N sets would duplicate every event ×N, and cross-set delivery would outrun the reader's own graph), player ephemera + heartbeats ride the ONE cluster mesh redis (one publisher per event — the owning server). - 2026-08-14 · WORLD RECIPE BOUNDARY (owner, amended 2026-08-18): the game passes one plain seed-authored world recipe into the engine; the recipe maps all nine temperature × humidity slots to biome names, and each biome owns one piecewise-linear landscape threshold/elevation curve whose selected knots may change semantic strata with bounded material-boundary variance.
